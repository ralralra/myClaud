## 2. 1단계 코드 구조 해부 (2차시용)

로봇팔 코드는 결국 이 한 문장으로 요약된다.
**"조이스틱 값을 읽어서(`analogRead`) → 각도를 정하고(`+1/−1`) → 서보에 쓴다(`write`)."**

### 2-1. 배열로 6개 서보를 한 번에 관리
```cpp
const int SERVOS = 6;
int PIN[SERVOS];        // 각 서보의 핀 번호
int MIN[SERVOS], MAX[SERVOS];   // 각도 제한(안전장치)
Servo myservo[SERVOS]; // 서보 객체 6개
```
서보가 6개라서 변수를 6벌 만드는 대신 **배열 + `for`문**으로 처리한다.
"왜 배열을 썼을까?"가 좋은 발문이다. (→ 6줄을 1줄로, 수정도 한 곳에서)

### 2-2. setup() — 딱 한 번, 초기 설정
```cpp
myservo[i].attach(PIN[i]);      // i번 서보를 핀에 연결
myservo[i].write(INITANGLE[i]); // 초기 각도로 이동
```

### 2-3. loop() — 계속 반복, 실제 조작
```cpp
value[i] = analogRead(ANA[i]);   // 0~1023
if (value[i] > 612) ... ++currentAngle  // 한쪽으로 밀면 +
else if (value[i] < 412) ... --currentAngle  // 반대로 밀면 −
else  ... // 가운데(412~612)는 "중립" → 멈춤
```
- `612`, `412`는 **조이스틱 중립 구간(데드존)** 경계다. 가운데 1023/2≈512 주변을 멈춤으로 둔 것.
- 이 두 숫자를 바꿔보게 하면(예: 312/712) 조이스틱 민감도가 달라진다 → 살아있는 실험.

### 2-4. "코드 탐정" 실험 거리 (2차시 미션용)
- `delay(50)` → `delay(10)` : 더 빠르게(거칠게) 움직인다.
- `MAX[5] = 90` → `45` : 그리퍼가 덜 닫힌다. 왜?
- `PIN`을 일부러 바꾸기 : 엉뚱한 관절이 움직인다 → 핀 매핑의 의미 체감.

## 3. 함수 만드는 법 (9차시 핵심)

### 3-1. 왜 함수가 필요한가 — "복붙의 고통"에서 출발
자동으로 물체를 옮기려면 이런 코드를 계속 써야 한다.
```cpp
myservo[0].write(90); myservo[1].write(130); myservo[2].write(110); // ... 6줄
delay(500);
```
자세를 옮길 때마다 이 6줄을 **복사·붙여넣기** 해야 하고, 한 곳만 틀려도 망가진다.
→ "반복되는 덩어리에 **이름**을 붙이자"가 함수의 출발점이다.

### 3-2. 함수의 3요소
```cpp
void goHome() {          // ① 이름(goHome)  ② void = 돌려주는 값 없음
  moveTo(HOME);          // ③ 중괄호 안 = 할 일
}
```
이제 어디서든 `goHome();` 한 줄이면 홈 자세로 간다.

### 3-3. 매개변수(parameter) — 함수를 "재사용"하게 만드는 핵심
같은 동작인데 목표만 다를 때, 목표를 **괄호로 받는다**.
```cpp
void moveTo(int target[]) {   // target(목표 자세 배열)을 받아서
  // 팔(1~5번)을 target 쪽으로 1도씩 부드럽게 이동 (그리퍼는 제외)
}
```
호출할 때 값만 바꿔 넣으면 된다.
```cpp
moveTo(PICK);     // 집는 자세로
moveTo(PLACE);    // 놓는 자세로
```
함수 하나로 **모든 자세 이동**을 처리한다. 이게 "함수의 힘"이다.

### 3-4. 학생이 직접 만들어 볼 함수 (실습 단계)
1. `gripperOpen()` / `gripperClose()` — 그리퍼만 여닫기 (가장 쉬움, 첫 함수로 좋음)
2. `goHome()` — `moveTo`를 부르는 한 줄짜리 함수
3. `wave()` — 손 흔들기 같은 자유 함수(재미 요소)
4. `autoPickAndPlace()` — 위 함수들을 **순서대로 나열**하면 자동화 완성

### 3-5. 자동화의 정체 — "함수를 순서대로 부르기"
```cpp
void autoPickAndPlace() {
  gripperOpen();       // 손을 펴고
  moveTo(PICK_READY);
  moveTo(PICK);
  gripperClose();      // 집고
  moveTo(PICK_READY);
  moveTo(PLACE);
  gripperOpen();       // 놓고
  goHome();
}
```
학생이 8차시에서 기록한 각도값을 `HOME/PICK/PLACE` 배열에 넣으면
**자기 로봇팔 전용 자동 동작**이 된다. 추상적이지 않고 즉시 손에 잡힌다.

## 4. 버튼(조이스틱 SW)으로 실행하기

이 수업에서는 **조이스틱 SW핀에 버튼 선을 하나 추가**해서 쓴다.
`08_` 코드는 그 버튼을 디지털 **7번 핀**으로 읽도록 되어 있다(핀은 배선에 맞게 수정).

- 배선: 조이스틱 SW → 디지털 7번,  GND → GND.
  SW는 누르면 GND와 연결되므로 `INPUT_PULLUP`을 쓰고, **눌림 = LOW**로 읽는다.
- 코드 동작: 버튼이 `HIGH→LOW`로 바뀌는 **'눌리는 순간'에만** 한 번
  `autoPickAndPlace()`를 실행한다(`delay(20)`으로 채터링 방지).

```cpp
pinMode(BUTTON_PIN, INPUT_PULLUP);      // setup()
...
boolean nowButton = digitalRead(BUTTON_PIN);     // loop()
if (lastButton == HIGH && nowButton == LOW) {    // 방금 눌림
  delay(20);
  if (digitalRead(BUTTON_PIN) == LOW) autoPickAndPlace();
}
lastButton = nowButton;
```

> 시리얼 명령(`1`/`h`/`p`)도 그대로 살려 두었다. 버튼 배선이 헷갈릴 때나
> 디버깅할 때 시리얼로 먼저 확인하고, 완성되면 버튼으로 시연하면 좋다.

### 그리퍼 각도 (이 로봇팔 기준)
- **열림 = 0도, 닫힘 = 90도** → 코드의 `GRIP_OPEN = 0`, `GRIP_CLOSE = 90`.
- **중요:** `moveTo()`는 팔(1~5번)만 움직이고 **그리퍼는 건드리지 않는다.**
  옮기는 도중에 손이 멋대로 열려 물체를 떨어뜨리지 않게 하기 위함이다.
  그리퍼는 항상 `gripperOpen()` / `gripperClose()`로만 여닫는다.

## 5. 자주 나는 문제 (교사 체크리스트)
- 전원 켜자마자 팔이 크게 튄다 → 초기각(`INITANGLE`)이 실제 안정 자세와 다름(4차시에서 교정).
- 그리퍼가 끝까지 안 닫힌다 → `GRIP_CLOSE`/`MAX[5]` 값을 물체 두께에 맞게 조정.
- 자동 동작이 너무 빨라 물체를 친다 → `moveTo`의 `stepDelay`를 키운다.
- 서보가 떨린다(지터) → 전원 용량 부족일 수 있음. USB만으로 6축 구동 시 외부 전원 권장.
