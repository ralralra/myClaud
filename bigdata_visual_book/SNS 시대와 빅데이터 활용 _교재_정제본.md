# 제1부. 데이터 리터러시: 숫자가 말을 걸다

오늘날 우리는 눈을 뜨는 순간부터 잠들기 전까지 온라인에 수많은 자취를 남긴다. 심지어 자는 동안에도 스마트 워치는 나의 몸 상태를 체크해 기록한다. 아침에 일어나면 알람을 끄고, 날씨를 확인하고, 내비게이션으로 빠른 길을 검색하거나 버스카드를 태그하고, 근처 카페에서 좋아하는 모닝커피를 결제하고, 배달 앱으로 음식을 주문하며, 플랫폼에서 영상을 시청하고, 좋아요를 누르거나 댓글과 상품평을 남기는 모든 행위가 다양한 디지털 형태로 꼼꼼히 저장되고 있다.

이러한 기록은 종이에 적힌 일기처럼 눈에 보이지는 않지만, 컴퓨터의 로그 파일처럼 차곡차곡 쌓인다. 우리가 무심코 남기는 일상의 흔적은 디지털 공간에서 하나의 데이터 조각이 되며, 이 조각들이 모여 개인의 행동 패턴과 사회의 흐름을 보여주는 중요한 단서가 되고 있다. 즉, 데이터란 특별한 전문가만 다루는 추상적인 개념이 아니라, **우리의 일상 그 자체가 숫자와 기록의 형태로 변환된 결과물**이라고 할 수 있다.

### 1.1 SNS: 데이터가 태어나는 가장 선명한 공간

IT·ICT가 일상화된 스마트 시대, SNS는 우리가 데이터를 생성하는 과정이 가장 실시간으로, 가장 선명하게 드러나는 공간이다. 스마트폰 사용자들은 깨어 있는 거의 모든 시간 동안 SNS로 자신의 감정과 행동 데이터를 쏟아낼 수 있을 뿐 아니라, 스마트폰에 내장된 GPS·가속 센서·거리 센서 등도 시시각각 사용자의 상황 정보를 양산하고 있다.

스마트폰에서 생성되는 데이터는 문자, 이미지, 영상, 클릭 스트림, 대화 기록, 소셜 미디어 플랫폼, 사물 인터넷(IoT) 데이터로 매우 다양하다. 이 외에도 기관에서 제공하는 공공데이터, 레거시 데이터베이스, 데이터를 스트리밍하는 실시간 데이터 등이 다양한 플랫폼에서 동시에 만들어진다. 플랫폼에 가입하는 과정에서 성별, 생년월일, 거주 지역 같은 기본 정보가 입력되고, 이 등록 정보는 배송·서비스 제공·계정 관리라는 명목 아래 자연스럽게 수집된다. 이용자는 단순히 서비스를 이용한다고 느끼지만, 데이터 분석가의 관점에서 보면 전혀 다른 그림이 그려진다.

| 📌 **읽을거리 — 사례 ①: 이커머스에서 일어나는 일상적 데이터 수집** |
| :---- |
| 우리가 매일 사용하는 쿠팡 같은 이커머스 플랫폼에는 어떤 데이터가 쌓이고 있을까? 단순히 이름과 전화번호뿐일까? 아니다. 무심코 누른 ‘구매’ 버튼은 생각보다 훨씬 많은 것을 기업에 알려준다. 주로 주문하는 시간대를 보면 언제 활동하고 언제 자는지 알 수 있다. 거주 환경도 드러난다. 배송 주소와 그 변경 빈도를 통해 어디에 사는지, 이사를 얼마나 자주 다니는지 알 수 있다. 무엇을 샀느냐는 더욱 결정적이다. 기저귀나 분유를 사면 아이를 키우는 집이고, 사료를 사면 반려동물과 함께 사는 집이라는 게 명확해진다. 결국 구매 단가와 브랜드 선호도가 연결되면 그 사람의 소득 수준과 소비 성향까지 추론이 가능해진다. 개별 데이터는 평범해 보이지만, **연결되는 순간 한 사람의 ‘삶의 지도’가 완성된다.** |

| 📌 **읽을거리 — 사례 ②: 데이터가 말하는 것들** |
| :---- |
| 좀 더 구체적인 상황으로 들어가 보자. <br>**“인천에 거주하는 30대 여성이 밤 10시에 로그인하여 최근 유행하는 남성 구두를 구매했다.”** <br>이 한 문장은 단순한 구매 기록처럼 보이지만, 여러 데이터가 축적되면 다음과 같은 정보 인식이 가능하다. <br>● 거주 지역과 주거 형태 (인천)<br>● 온라인 활동 시간대 (야간 활동 여부)<br>● 가족 구성이나 선물 소비 가능성 (본인이 아닌 남성 아이템 구매)<br>● 유행에 대한 민감도와 소비 성향 (최신 트렌드 반응) |

SNS에서 누르는 ‘좋아요’, 무심코 입력한 해시태그, 구매 이력, 특정 콘텐츠에 머무는 시간, 자주 가는 사이트 — 이 모두가 의미 있는 행동 데이터로 해석된다. 이용자의 의도와 무관하게 생성되는 이러한 데이터는 디지털 시대의 정보 환경에서 마치 땅속 깊이 묻혀 있던 원유처럼 빅데이터의 가치 있는 자원이 된다.

이렇게 분석된 데이터는 우리에게 ‘편리함’이라는 이름으로 돌아온다. AI는 나이와 성별에 맞게 상품을 추천하고, 경쟁사 가격을 실시간으로 모니터링해 최저가를 유지한다. 또한 우리가 다음에 무엇을 주문할지 미리 예측해 물류 센터에 물건을 배치하고, 로봇이 움직여 로켓 배송을 가능하게 만든다. 데이터가 쌓일수록 서비스는 정교해지고, 우리는 그 편리함에 더 의존하게 된다.

> 데이터는 우리 삶을 풍요롭게 만드는 강력한 도구이지만, 동시에 **나의 모든 사생활이 ‘해석’될 수 있다**는 점을 함께 생각해야 한다.

전 세계 수십억 명의 인구가 사용하는 SNS는 수십억 개의 인생을 들여다볼 수 있는 창구가 된다. 그래서 최근 빈번하게 발생하는 개인정보 유출 사고는 단순한 계정 탈취가 아닌, **한 사람의 인생 전체가 노출되는 사고**로 봐야 한다.

### 1.2 알고리즘이 만드는 개인화된 세상

수집된 방대한 데이터는 플랫폼의 알고리즘을 통해 분석되고, 우리가 보는 정보의 형태를 결정한다. 특정 유형의 영상을 자주 시청하면 추천 목록 상단에 유사한 주제가 나타나고, 음식 리뷰를 자주 보면 관련 식당 광고가 등장하는 방식이다. 플랫폼은 우리의 행동 패턴을 기반으로 ‘관심사’와 ‘선호도’를 예측하여 우리만을 위한 맞춤형 정보 환경을 구성한다.

#### 알고리즘은 어떻게 작동하는가

추천 알고리즘의 핵심은 **협업 필터링(Collaborative Filtering)**과 **콘텐츠 기반 필터링(Content-based Filtering)** 두 가지 방식이다.

- **협업 필터링** — ‘나와 비슷한 취향을 가진 사람들이 좋아한 것’을 추천하는 방식
- **콘텐츠 기반 필터링** — ‘내가 이미 좋아한 것과 유사한 특성을 가진 것’을 추천하는 방식

현재 대부분의 플랫폼은 이 두 가지를 결합한 **하이브리드 방식**을 사용한다. 유튜브의 경우 사용자가 어떤 영상을 끝까지 봤는지, 중간에 껐는지, 좋아요를 눌렀는지, 댓글을 달았는지를 모두 가중치로 계산한다. 단순히 클릭 수가 아니라 **시청 지속 시간(Watch Time)**을 핵심 지표로 삼는다. 넷플릭스는 여기서 더 나아가 사용자가 특정 장면에서 일시 정지했는지, 되감기 했는지, 어떤 시간대에 시청했는지까지 분석해 다음 콘텐츠를 결정한다. 넷플릭스가 공개한 자료에 따르면, 사용자가 플랫폼에서 보는 콘텐츠의 약 **80%가 알고리즘 추천에 의해 선택된다**.

| 📌 **읽을거리 — 사례: 같은 검색어, 다른 결과** |
| :---- |
| 동일한 검색어를 입력해도 사람마다 다른 결과가 나타난다. 예를 들어 ‘코로나 백신’을 검색했을 때, 과학 채널을 주로 시청하는 사람과 음모론 관련 영상을 자주 본 사람은 전혀 다른 정보를 보게 된다. 알고리즘은 ‘정확한 정보’가 아닌 **‘그 사람이 오래 볼 것 같은 정보’**를 우선적으로 보여주기 때문이다. <br>플랫폼 입장에서 알고리즘의 목표는 사용자가 플랫폼에 더 오래 머무르게 하는 것, 즉 **체류 시간(Engagement Time)의 극대화**이지, 정보의 정확성이나 다양성이 아니다. |

결국 우리는 추천 시스템의 편리함 속에서 스스로 정보를 선택한다고 생각하지만, 사실은 인공지능 알고리즘에 의해 안내된 소비를 하고 있는 것이다. 효율적인 일상에 동화되어 가면서, 우연한 발견의 기쁨과 낯선 관점을 만날 기회를 나도 모르게 잃어버리게 된 것은 아닐까.

### 1.3 편리함의 그림자: 필터 버블(Filter Bubble)

이러한 개인화 환경은 우리에게 큰 편리함을 주지만, 동시에 정보의 다양성을 제한하는 결과를 초래하기도 한다. 플랫폼이 이용자가 좋아할 만한 콘텐츠만 반복적으로 보여주다 보니, 특정 주제나 관점의 정보에만 갇히게 되는 현상이 발생하는데, 이를 **‘필터 버블(Filter Bubble)’**이라고 부른다. 인터넷 활동가 일라이 패리저(Eli Pariser)가 2011년 TED 강연에서 처음 대중화한 개념으로, 알고리즘이 사용자의 과거 행동을 기반으로 정보를 걸러냄으로써 그 사람만의 ‘정보 거품’ 안에 가두는 현상을 말한다.

#### 필터 버블 vs. 에코 챔버: 무엇이 다른가

필터 버블과 함께 자주 등장하는 개념이 **에코 챔버(Echo Chamber)**다. 둘 다 정보의 편향을 일으킨다는 점에서 비슷해 보이지만, 원인이 다르다.

| 구분 | 필터 버블 | 에코 챔버 |
| :--- | :--- | :--- |
| 원인 | 알고리즘이 자동으로 걸러냄 | 사람이 스스로 비슷한 생각의 집단 선택 |
| 인식 여부 | 사용자가 인식하기 어려움 | 어느 정도 의식적 선택 포함 |
| 대표 공간 | 유튜브, 인스타그램 피드, 구글 검색 | 특정 커뮤니티, 단체 채팅방, 팬덤 |

필터 버블이 더 위험한 이유는 사용자가 **인식조차 하지 못하는 상태에서** 정보가 제한되기 때문이다. 에코 챔버는 적어도 그 공간을 선택했다는 의식이 있지만, 필터 버블은 내가 원하는 정보를 보고 있다고 착각하는 상태에서 이미 편향된 정보 환경 안에 있는 것이다.

| 📌 **읽을거리 — 실제 사례: 선거와 필터 버블** |
| :---- |
| 2016년 미국 대통령 선거에서 많은 사람들이 자신이 지지하는 후보가 압도적으로 이길 것이라고 예측했다가 결과에 충격을 받았다. SNS 피드에 자신과 같은 성향의 의견만 가득했기 때문에 반대 진영의 여론을 전혀 실감하지 못했던 것이다. 이후 학계에서는 소셜 미디어 알고리즘이 정치적 양극화를 심화시킨다는 연구들이 본격적으로 등장했다. 퓨 리서치 센터(Pew Research Center)의 조사에 따르면, 미국 성인의 64%가 SNS에서 본 정보로 인해 놀라거나 혼란을 경험했다고 응답했으며, 그 원인 중 하나로 **알고리즘의 선별적 정보 노출**을 꼽았다. |

| 📌 **읽을거리 — AI와 필터 버블: 학습 데이터의 편향** |
| :---- |
| 필터 버블은 사람에게만 일어나는 현상이 아니다. 인공지능을 학습시킬 때 특정 방향으로 편향된 데이터만 반복적으로 주입되면, AI 역시 그 편향된 방향으로 판단을 내리게 된다. 인간도 학습된 환경에 따라 선입견이 생기지만 이를 인식하고 수정할 수 있다. 반면 AI는 학습 데이터 자체가 왜곡되어 있으면 스스로 그 사실을 알아차리기 어렵다. **그래서 인공지능이 도출한 결과값에 맹목적인 신뢰를 보이는 것은 쉽게 생각할 문제가 아니다.** |

#### 필터 버블에서 벗어나려면

그렇다면 우리는 어떻게 해야 할까? 몇 가지 실천 가능한 방법이 있다.

- **의도적으로 다른 관점의 콘텐츠 소비하기** — 평소와 다른 성향의 매체나 채널을 의식적으로 찾아보는 것
- **플랫폼 추천 알고리즘 초기화** — 유튜브, 넷플릭스 등 대부분의 플랫폼은 시청 기록 삭제 및 관심사 재설정 기능을 제공한다
- **검색 엔진 다양화하기** — 같은 키워드를 여러 검색 엔진에서 검색해 결과를 비교하는 습관
- **정보 출처 교차 확인하기** — 하나의 플랫폼, 하나의 채널에만 의존하지 않고 출처를 다각화하는 것

정보가 넘쳐나는 시대에 중요한 것은 얼마나 많은 정보를 접하느냐가 아니라, **얼마나 다양한 관점의 정보를 균형 있게 볼 수 있느냐**다. 데이터 리터러시의 시작은 바로 ‘내가 지금 보고 있는 정보가 어떻게 선별된 것인지’ 묻는 질문에서 비롯된다.

### 1.4 정보에서 지능으로: 데이터 리터러시의 시작

필터 버블이 보여주듯, 데이터는 우리를 편리하게도 하지만 동시에 우리가 모르는 사이 정보를 제한하기도 한다. 그렇다면 이 환경 속에서 우리에게 필요한 능력은 무엇일까? 답은 데이터를 ‘읽고 판단하는 힘’, 즉 **데이터 리터러시(Data Literacy)**다.

**데이터 리터러시란** 데이터를 단순히 읽는 것을 넘어, 데이터가 어디서 왔는지, 어떻게 수집되었는지, 무엇을 말하고 있는지, 그리고 무엇을 말하지 않는지를 파악하는 능력이다. 쉽게 말해 숫자와 그래프 앞에서 ‘이게 진짜인가?’를 물을 수 있는 비판적 사고력이다. 데이터가 넘쳐나는 시대일수록 많은 정보를 접하는 것보다 정보를 제대로 해석하는 능력이 훨씬 중요해진다.

**데이터가 지능이 된다는 것은 무슨 뜻일까?** 감이나 경험에만 의존하지 않고, 데이터와 숫자를 보고 더 나은 선택을 하는 것을 말한다. 이를 **‘데이터 기반 의사결정’**이라고 부른다. 결과적으로 SNS 시대의 정보 경험은 단순한 소비 활동이 아닌, 개인이 생성한 데이터가 다시 개인의 정보 환경을 구성하는 순환 구조다. 데이터는 곧 나 자신을 나타내게 된다.

| 📌 **읽을거리 — 사례: 같은 옷, 다른 매출** |
| :---- |
| 서울 홍대와 가로수길에 위치한 똑같은 여성 의류 전문 매장에서 똑같은 제품의 똑같은 할인폭을 가진 행사가 진행되었다. 하지만 두 곳의 매출 결과는 전혀 달랐다. 홍대 매장은 매출이 급등한 반면, 가로수길 매장은 평소와 큰 차이가 없었다. <br>왜 그럴까? 두 매장의 신용카드 구매 기록 데이터를 분석해 봤다. 홍대 매장에서는 대부분 여성의 신용카드가 사용되었지만, 가로수길 매장에서는 남성의 신용카드로 결제하는 경우가 많았다. 즉 홍대에서는 자신의 돈으로 옷을 사 입는 여성 고객이 대부분이었고, 가로수길 매장에서는 **남성이 여성에게 선물로 사 주는 경우가 많았던 것**이다. |

#### 데이터 기반 의사결정이란

예를 들어 카페 사장님이 “내 생각엔 딸기 음료가 인기 있을 것 같아”라고 추측하는 대신, 지난달 판매 데이터를 보고 실제로 가장 많이 팔린 메뉴를 확인한다면? 손해를 줄이고 매출을 높일 수 있다. 넷플릭스가 당신이 본 영화와 드라마 기록을 분석해서 “이 작품도 좋아하실 것 같아요”라고 추천하는 것도 같은 원리다.

이처럼 데이터를 잘 활용하면 시간과 돈을 아끼고, 더 좋은 결과를 만들 수 있다. 데이터는 우리가 효율적이고 더 현명한 선택을 할 수 있도록 도와주는 든든한 조력자다. 따라서 데이터가 수집되고 활용되는 환경을 이해하고, 데이터를 비판적으로 읽어내는 데이터 리터러시 역량을 갖추는 것은 디지털 사회를 살아가는 모든 사람에게 가장 필수적인 출발점이다.

### 2.1 데이터의 무게: 0과 1에서 제타바이트(ZB)까지

데이터는 형체가 없지만 분명한 ‘크기’와 ‘단위’를 가지고 있다. 컴퓨터를 구매하거나 이메일에서 파일을 첨부할 때 많이 들어 본 **비트(bit)**와 **바이트(Byte)** 같은 단위가 그것이다. 이는 컴퓨터가 계산을 시작했을 때부터 사용하던 기계어의 용량을 표현하는 단위로, 기계가 전기 신호의 ‘있다 / 없다’를 판단하는 **이진수(0 또는 1) 논리**를 바탕으로 데이터를 처리한다.

2진법 수 체계는 “현대 디지털 정보통신의 아버지”라고 불리는 미국의 수학자 **클로드 섀넌(Claude Shannon)**이 정보의 전자적 전달을 위해 정의한 원리이다. 우리가 흔히 보는 전원 버튼의 모양도 0과 1을 합쳐 만든 표시이다. 0과 1은 인간의 눈에는 숫자로 보이지만 컴퓨터 안에서는 **전기 신호가 있느냐 없느냐**로 표현된다. 먼 거리에 정보를 전달할 수 있는 인터넷, 그리고 친구에게 문자나 사진을 주고받을 수 있는 환경은 모두 클로드 섀넌 덕분이라 할 수 있다. 1937년 그가 발표한 논문 「전기와 스위칭 회로의 기호학적 분석」은 디지털 컴퓨터의 기본 개념이면서 20세기에 가장 중요하고 유명한 석사학위 논문이 되었다.

**0과 1, 두 가지 중 하나를 정하는 것이 바로 1비트(1 bit)이며, 이것이 정보(데이터)의 양을 측정하는 기준이 되었다.**

![][온오프] ![][스위치] ![][셰넌]

전기 신호를 0과 1로 처리함으로써 컴퓨터는 무한한 가능성을 갖게 되었다. 전기 신호의 유무를 판단하는 과정이 모이면 숫자 계산이 가능해지고, 사람의 언어도 판독할 수 있게 된다. 이러한 특징은 **소리·이미지·영상·텍스트** 같은 질적으로 다른 정보들을 숫자로 변환했을 때 모두 2진수 데이터로 처리할 수 있다는 논리로 확장된다. 센서의 발명으로 소리·냄새·촉감·거리·컬러·위치 등의 감지가 전기 신호로 바뀌고, 전기 신호는 10진수로, 10진수는 2진수로 처리되어 데이터화된다.

| 📌 **읽을거리 — 천공카드에서 OMR로** |
| :---- |
| 다음 이미지는 천공카드(punched card)이다. 종이에 구멍을 뚫어 0/1을 기록한 2진수 명령어로, 시험 볼 때 사용하던 OMR 카드와 비슷하다고 생각하면 이해하기 쉽다. **OMR(Optical Mark Recognition)** 기술은 사실상 천공카드 시스템의 진화된 형태이다. 천공카드는 종이에 물리적 손상(구멍)을 입혀야 하므로 수정이 불가능하고 내구성이 취약했지만, OMR은 종이를 훼손하지 않고 **빛의 반사와 흡수 신호만으로 판독**함으로써 천공카드의 단점을 보완한 사례이다. <br>![][omr]   ![][천공카드] |

데이터의 양이 폭증하면서 그 단위도 기하급수적으로 커졌고, 그에 따라 처리 속도와 저장 공간 등 데이터를 잘 보관하고 활용할 수 있는 방안이 함께 발전하기 시작했다.

- **1 비트(bit)** — 0과 1 중 하나의 신호를 저장할 수 있는 최소 단위. 8개가 모이면 8비트, 즉 1바이트가 된다.
- **1 바이트(Byte) = 8 비트** — 글자 한 개를 저장할 수 있는 용량.
- **단위의 팽창** — 킬로(KB) → 메가(MB) → 기가(GB) → 테라(TB)를 넘어, 이제는 해변의 모래알보다 많은 정보를 뜻하는 **제타바이트(ZB), 요타바이트(YB) 시대**로 진입하고 있다.

### 2.2 데이터 증가의 이유

인공지능이 처음 제기됐을 때부터 전 세계 수학자와 컴퓨터 공학자, 뇌과학자 등이 함께 연구를 했지만 쉽게 발전하지 못했던 이유 중 하나는 **데이터의 양**이었다. 인공지능이 학습해야 할 재료가 부족하면 학습 부진으로 이어지고, 인간이 놀랄 만한 수준의 성과를 낼 수 없었다. 하지만 전 세계인이 컴퓨터보다 훌륭한 스마트폰을 항상 손에 들고 다니며 데이터를 생산하는 오늘날이라면 이야기가 달라진다.

인터넷에서는 단 1분이라는 짧은 시간 동안에도 폭발적인 데이터 생성과 소통이 일어난다. 유튜브(YouTube)에는 500시간 이상의 영상이 업로드되고, 3,500만 건의 메시지 전송과 수백만 건의 구글 검색이 동시에 실행된다. 이런 빅데이터를 처리하기 위해 전 세계 전력의 약 10%가 소비되며 7,500만 대 이상의 서버가 가동된다. 동시에 CPU(직렬 처리 연산), GPU(병렬 처리 연산)도 발전하여 처리·계산 속도가 빨라지고, 데이터 저장장치도 64GB 정도의 용량을 손톱만 한 곳에 보관할 수 있을 정도로 작아졌다. 데이터는 **인터넷, 스마트폰의 대중화, 컴퓨터와 반도체의 꾸준한 업그레이드**로 증가했다고 볼 수 있다. 이제는 거의 대부분의 자료를 디지털화하여, 전 세계 의료 데이터만 해도 2025년까지 매년 약 36%씩 증가하고 있다.

#### 데이터가 폭증한 7가지 원인

1. **모바일 기기의 폭발적 증가** — 스마트폰 사용자가 전 세계적으로 수십억 명에 달하면서 데이터 생성량이 급증했다. 매일 사진과 동영상을 촬영하고, SNS에 게시물을 올리며, 인스턴트 메시지로 대화를 나눈다. 특히 고화질 사진(한 장당 수 MB)과 4K 동영상(1분당 수백 MB)의 보편화로 개인이 생성하는 데이터량은 더욱 기하급수적으로 늘었고, 실시간 스트리밍 서비스(유튜브·넷플릭스 등)의 대중화로 영상 데이터 소비와 생성도 폭증했다.

2. **사물인터넷(IoT) 기기의 확산** — 스마트홈 기기(AI 스피커·스마트 조명·온도 조절기), 자율주행차량의 센서, 공장의 스마트 설비 등 수많은 IoT 기기들이 24시간 실시간으로 데이터를 수집·전송한다. 자율주행차 한 대는 하루에 약 4 TB의 데이터를 생성하며, 이는 센서·카메라·GPS 등에서 나오는 방대한 정보다. 이를 활용해 지도 앱은 차량의 속도나 밀집도를 분석해 밀리는 구간과 빠른 길을 안내한다.(여기서 자율주행 자동차는 현재 보편화되어 있는 1~3단계 레벨을 말한다.)

3. **소셜 미디어와 온라인 활동** — 페이스북·인스타그램·X·틱톡 등의 플랫폼에서 매 초 수백만 개의 게시물·댓글·좋아요가 생성된다. 사용자들의 프로필 정보, 관계망, 행동 패턴까지 모두 데이터로 저장되며, 이는 광고 타깃팅과 추천 알고리즘에 활용된다.

4. **전자상거래와 금융 거래** — 온라인 쇼핑의 증가로 구매 이력, 장바구니 정보, 상품 리뷰, 결제 기록, 결제 시간 등이 대량으로 축적된다. 신용카드 및 모바일 결제 시스템은 모든 거래 내역을 실시간으로 기록하며, 이는 사기 탐지와 소비/생활 패턴 분석에 활용된다.

5. **기업과 공공 부문의 디지털 전환** — 기업들이 종이 문서를 디지털화하고 CRM·ERP 시스템을 도입하면서 업무 데이터가 증가했다. 공공기관도 전자정부·스마트시티 사업을 통해 교통·환경 센서·기상청·민원 데이터를 수집·분석하여 공익적 환경 조성에 활용한다. 저출산 고령화 문제도 출생·사망 신고 인구 데이터를 분석해 미래를 예측하는 데 사용되며, 우리나라의 기온 데이터는 **1904년**부터 수집되기 시작했다.

6. **과학 연구와 빅사이언스** — 유전체 분석(한 사람의 전체 유전자 정보는 약 200 GB), 우주 관측, 기후 모델링 등 과학 연구에서 수집·생성되는 데이터도 막대하다. 유럽입자물리연구소(CERN)의 대형강입자충돌기(LHC)는 연간 수십 페타바이트(PB)의 데이터를 생성하며, 기후 데이터나 우주 관측은 실시간으로 꾸준히 기록되고 있다.

7. **법적 보관 의무와 인공지능 학습 데이터** — 많은 산업 분야에서 데이터를 일정 기간(5년·10년 이상) 보관하도록 법적으로 규정한다. 금융권의 거래 기록, 의료 기록, 통신 기록 등이 삭제되지 않고 계속 축적된다. 또한 AI 모델을 학습시키기 위해서는 방대한 훈련 데이터가 필요하므로 이미지 인식·자연어 처리·음성 인식용 데이터가 수십억 건씩 수집된다.

이러한 다양한 요인들이 복합적으로 작용하면서, 우리가 생성하고 저장하는 데이터의 양은 매년 두 배 이상씩 증가하고 있으며, 이 속도는 앞으로 더욱 빨라질 것이다.

| 📌 **읽을거리 — 의료 데이터의 저장 방식** |
| :---- |
| · **전자의무기록(EMR/EHR)** — 병원에서는 환자의 진료 기록·예방접종 실시 유무·검사 결과·처방전 등을 전자의무기록 시스템에 저장한다. 과거 종이 차트에서 디지털 데이터베이스로 전환되면서 데이터 양이 급증했다. <br>· **의료 영상 데이터(PACS)** — CT·MRI·X-ray 등 의료 영상은 매우 큰 용량을 차지한다. 한 장의 고해상도 CT 스캔은 수백 MB에서 수 GB에 달하며, 이는 별도의 **의료영상저장전송시스템(PACS)**에 보관된다. <br>· **웨어러블 기기 데이터** — 스마트워치나 건강 밴드가 실시간으로 수집하는 심박수·활동량·수면 패턴 등의 데이터가 클라우드 서버에 지속적으로 축적된다. <br>· **병원 정보시스템(HIS)** — 진료 예약·수납·보험 청구 등 병원 운영 관련 모든 데이터도 통합 정보시스템에 저장된다. <br><br>의료 데이터가 매년 36%씩 성장하는 이유는 정밀 의료와 예방 의학의 확산, 웨어러블 기기의 대중화, 인공지능 진단을 위한 학습 데이터 축적, 그리고 법적으로 의료 기록을 장기간 보관해야 하는 규정 때문이다. 이러한 방대한 데이터를 분석하면 **질병 조기 발견·개인 맞춤형 치료·신약 개발** 등에 활용할 수 있어, 의료 데이터는 곧 생명을 구하는 자원이 된다. |

### 2.3 빅데이터: 3V에서 6V로

**빅데이터(Big Data)**란 수치로 명확하게 표현되는 기존의 정형화된 자료에 비정형화된 이미지·동영상·문자·언어 등이 포함된, **거대하고 다양하며 실시간**의 특징을 갖는 자료를 말한다. 최근에는 대용량 데이터 수집·저장·플랫폼·분석 기법 등을 포괄하는 용어로 변화하고 있다.

#### 정형 · 반정형 · 비정형 데이터

| 종류 | 특징 | 예시 |
| :--- | :--- | :--- |
| **정형 데이터** | 즉시 통계적 분석에 사용될 수 있는 형태로 정리·가공된 데이터 | 엑셀 테이블, 관계형 데이터베이스 |
| **반정형 데이터** | 고정된 양식은 없으나 구조나 규칙이 있는 데이터 | HTML, log, JSON, XML |
| **비정형 데이터** | 정해진 규칙이 없어 값의 의미를 쉽게 파악하기 힘든 데이터 | 사진, SNS 글, 이미지, 영상 |

전체 빅데이터 중 약 **20%를 정형 데이터**가 차지하고 나머지 **80%를 비정형**이 차지하고 있으며, IBM 보고서에 따르면 **비정형 데이터의 증가율은 정형 데이터 증가율의 약 15배**에 이른다고 한다.

| 📌 **읽을거리 — 데이터는 어디를 흐르는가: 프론트엔드와 백엔드** |
| :---- |
| 우리가 눈으로 보고 직접 사용하는 화면, 즉 앱이나 웹사이트의 인터페이스를 **프론트엔드(Front-end)**라고 한다. 반면 사용자의 요청을 처리하고 데이터를 저장하는 서버 영역을 **백엔드(Back-end)**라고 한다. 검색창에 단어를 입력하는 순간, 그 정보는 프론트엔드를 통해 백엔드로 전달되고, 서버는 이를 처리한 뒤 결과를 다시 화면으로 보내 준다. 데이터는 **사용자 → 서버 → 사용자**의 흐름을 반복하며 끊임없이 이동한다. |

| 📌 **읽을거리 — 모든 행동은 기록된다: 로그 데이터** |
| :---- |
| 데이터 흐름의 핵심이 되는 것이 바로 **로그 데이터(Log Data)**다. 로그 데이터란 사용자의 행동이 시간 순서대로 기록된 데이터로, 검색한 키워드·클릭한 페이지·머문 시간·구매 이력·접속 위치 및 기기 정보가 모두 포함된다. 우리는 단순히 인터넷을 ‘사용’하는 것이 아니라, 동시에 데이터를 끊임없이 생성하고 있는 존재다. 이렇게 쌓인 로그 데이터는 기업에게는 사용자 행동을 이해하는 핵심 자료가 되고, 정부·공공기관에서는 정책 수립과 서비스 개선에 활용된다. |

| 📌 **읽을거리 — 시크릿 모드도 로그가 남을까?** |
| :---- |
| 많은 사람이 시크릿 모드를 사용하면 모든 기록이 사라진다고 생각한다. 그러나 이는 부분적으로만 맞는 이야기다. 시크릿 모드는 **브라우저에 검색 기록을 저장하지 않고 쿠키 및 로그인 정보를 자동 삭제**하는 기능만 제공할 뿐이다. 웹사이트 서버에 기록되는 접속 로그, 인터넷 서비스 제공자(ISP)의 접속 기록, 회사나 학교 네트워크의 접속 기록은 시크릿 모드와 무관하게 그대로 남는다. <br>시크릿 모드는 ‘내 컴퓨터에 기록이 남지 않게 하는 기능’일 뿐, 인터넷 전체에서 흔적을 지우는 기능이 아니다. 이 사실은 우리가 디지털 환경에서 얼마나 많은 데이터 흔적을 남기고 있는지를 잘 보여 준다. |

#### 데이터 흐름과 보안: 왜 암호화가 필요한가

데이터가 사용자와 서버 사이를 이동하는 과정에서는 **보안 문제**가 필연적으로 발생한다. 아이디와 비밀번호, 결제 정보, 개인정보처럼 민감한 데이터가 그 경로를 통해 오가기 때문이다. 이를 보호하기 위해 **암호화(Encryption)** 기술이 사용된다. 암호화란 데이터를 알아볼 수 없는 형태로 변환하여 허가된 사람만 다시 읽을 수 있도록 만드는 기술이다. 반대로 암호를 해독하려는 시도를 **복호화(Decryption)**라고 하며, 해커들이 노리는 것이 바로 이 지점이다.

따라서 데이터가 이동하는 전 과정은 **생성 → 전송 → 암호화 → 저장 → 복호화 및 활용**의 복합적인 구조 속에서 보안 시스템과 함께 작동한다. 오늘날 데이터는 단순한 기록을 넘어 의사결정과 예측을 가능하게 하는 핵심 자원이 되었다. 추천 알고리즘, 자율주행 시스템, 의료 인공지능, 금융 예측 시스템 모두 방대한 데이터를 기반으로 작동한다. 데이터의 가치가 커질수록 이를 노리는 공격도 함께 증가한다. 결국 빅데이터 시대의 핵심 원칙은 하나다.

> **“데이터가 많아질수록, 보안의 중요성도 함께 커진다.”**

#### 가트너의 3V, 그리고 5V·6V

미국의 세계적인 정보기술 연구·자문회사 **가트너(Gartner Inc.)**는 빅데이터의 핵심 요소를 **3V**로 정의했다.

| 속성 | 의미 |
| :--- | :--- |
| **Volume (규모)** | 테라바이트 이상의 방대한 데이터 양. ICT 발전으로 디지털 정보량이 급증하면서 ZB·PB 시대로 진입 중 |
| **Velocity (속도)** | 데이터가 실시간으로 빠르게 생성·처리·이동·시각화되는 특성 |
| **Variety (다양성)** | 정형 데이터뿐 아니라 사진·오디오·비디오·SNS·로그 파일 등 비정형 데이터의 다양성 |

이후 데이터 분석의 신뢰성과 가치가 강조되면서 다음 속성이 추가로 정의되었다.

| 속성 | 의미 |
| :--- | :--- |
| **Veracity (정확성)** | 방대한 데이터일수록 부정확한 데이터도 함께 증가한다. 패턴을 설명할 만큼 신뢰할 수 있는 데이터인지의 문제 |
| **Value (가치)** | 데이터 분석을 통해 얻을 수 있는 통찰력과, 현실적인 문제 해결에 도움이 되는가의 가치 |
| **Visualization (시각화)** | 복잡한 분석 결과를 정보 사용자가 쉽게 이해할 수 있도록 가공해 보여 주는 능력 |

핵심은 여전히 3V에서 출발하지만, 데이터를 ‘얼마나 정확하게 · 가치 있게 · 알기 쉽게’ 만드는가가 곧 빅데이터의 성패를 가른다.

### 2.4 데이터 리터러시: 숫자를 읽는 사람이 세상을 읽는다

데이터가 넘쳐나는 시대라고 해서 누구나 데이터를 잘 다루는 것은 아니다. 쏟아지는 숫자와 그래프 앞에서 ‘이게 맞는 말인가?’를 물을 수 있는 사람과, 그냥 받아들이는 사람 사이의 차이는 생각보다 크다. 이 차이를 만드는 것이 바로 **데이터 리터러시(Data Literacy)**다.

데이터 리터러시란 단순히 데이터를 읽는 능력이 아니다. **데이터가 어디서 왔는지, 어떤 목적으로 수집되었는지, 무엇을 말하고 있는지, 그리고 무엇을 말하지 않는지**까지 파악하는 종합적인 판단 능력이다. 세계경제포럼(WEF)은 2020년 미래 직업 보고서에서 데이터 리터러시를 향후 10년간 가장 중요한 핵심 역량 중 하나로 꼽았다. 데이터를 생산하는 기술은 빠르게 발전하지만, 그것을 제대로 읽고 판단하는 사람은 여전히 드물기 때문이다.

![][데이터분석프로세스]

#### 데이터를 다루는 사람들은 어떻게 일하는가

데이터 리터러시를 갖춘다는 것은 전문 개발자가 되는 것이 아니다. **데이터를 분석하고 활용하는 사고의 흐름**을 이해하는 것이다. 실제 데이터 분석은 다음의 다섯 단계를 거친다.

**1단계 — 문제 정의: 무엇을 알고 싶은가**
데이터 분석은 컴퓨터가 아니라 **질문**에서 시작된다. ‘무엇을 하고자 하는가, 얻고자 하는 결과는 무엇인가’가 명확하게 정의되어야 어떤 데이터를 수집할지, 어떤 모델을 사용할지 방향이 잡힌다. 문제 정의가 흐릿하면 아무리 많은 데이터를 갖고 있어도 의미 있는 결론을 끌어낼 수 없다.

**2단계 — 데이터 수집: 필요한 것만, 정확하게**
문제가 정의되면 어떤 종류의 데이터가 필요한지, 얼마나 확보할 수 있는지가 핵심 쟁점이 된다. 데이터는 많을수록 좋다고 생각하기 쉽지만, 필요 없는 데이터까지 수집하면 분석에 노이즈가 생긴다. **양보다 질**, 즉 목적에 맞는 정확한 데이터를 수집하는 것이 중요하다.

**3단계 — 데이터 분석: 패턴과 관계를 찾는 과정**
수집된 데이터에서 의미 있는 것은 무엇인지, 데이터의 분포와 연관 관계는 어떠한지를 살피는 단계다. 많은 데이터를 수집했더라도 처음에 정의한 문제에 적합하고 의미 있는 데이터를 걸러내는 것이 첫 번째 분석 작업이다. 서로 상관관계가 있거나 의미 있는 분포를 가진 데이터를 골라내야 핵심적이고 신뢰할 수 있는 분석 결과가 나온다. 이 과정에서 데이터를 정제하는 **전처리(Preprocessing)** 작업이 필요하다.

**4단계 — AI 모델링: 패턴을 학습시키다**
분석한 데이터에서 의미 있는 관계가 나왔다면, 어떤 모델링 알고리즘을 사용할 것인가가 중요해진다. **분류**를 할 것인지, **예측**을 할 것인지, **추천**을 할 것인지에 따라 알고리즘은 달라진다. 알고리즘에 학습을 시키면 인공지능 서비스로 쓰일 수 있는 형태가 된다.

**5단계 — AI 적용: 검증하고 또 검증하다**
학습된 인공지능이 실제 문제 해결에 사용되는 단계다. 그러나 한 번에 완벽할 수 없기에 **검증과 테스트** 과정을 반복해야 한다. 필요하다면 데이터를 추가로 수집하거나 분석 단계로 돌아가 다른 연관성을 찾아보는 순환 과정이 계속된다.

#### 숫자를 읽는 사람이 세상을 읽는다

이 다섯 단계는 데이터 과학자만의 이야기가 아니다. 카페 사장이 지난달 판매 데이터를 보고 인기 메뉴를 결정하는 것도, 학교 선생님이 학생 성취 데이터를 보고 수업 방식을 바꾸는 것도 같은 흐름이다. 규모가 다를 뿐, 과정은 동일하다.

데이터 리터러시는 특별한 사람들의 전문 기술이 아니다. **‘내가 지금 보고 있는 정보가 어떻게 만들어진 것인지, 이 숫자가 전체를 대표하는 것인지, 나에게 보여 주지 않는 것은 무엇인지’**를 묻는 습관에서 시작된다.

> **“데이터를 읽는 사람이 데이터에 끌려다니지 않는다.”**

지금까지 우리는 데이터가 어떻게 만들어지고, 어떻게 쌓이며, 어떻게 우리의 일상에 영향을 미치는지를 살펴보았다. 제2부에서는 이 데이터를 **눈에 보이게 만드는 기술**, 시각화(Visualization)의 세계로 들어간다. 숫자가 그림이 되는 순간, 데이터는 비로소 모두의 언어가 된다.

# 제2부. 데이터 시각화: 보이지 않는 마법의 지도

데이터는 컴퓨터와 스마트폰이 발명된 현대의 산물이 아니다. 인류는 아주 오래전부터 생존과 번영, 그리고 효율적인 국가 운영을 위해 쉼 없이 데이터를 수집하고 기록해 왔다. 보이지 않는 현상을 숫자와 문자로 남기려는 노력은 곧 문명의 진화 과정이었다.

## 제3장. 기록의 역사: 인류는 무엇을 남겼는가

> ### 핵심 질문

### 학습 목표

2. 조선의 양안과 측우기가 ‘데이터 기반 행정’의 사례임을 이해한다.

4. 인구조사가 국가 역량 계산에 어떻게 활용되었는지 이해한다.

### 3.1 기록의 기원: 문자는 곡식을 세기 위해 발명되었다

문자의 발명은 인간이 기억의 한계를 넘어설 수 있게 한 혁명적 사건이었다. 기록은 개인의 기억을 넘어 공동체의 기억이 되었고, 세대를 넘어 지식이 축적되기 시작했다.

그런데 왜 인류는 이토록 집요하게 기록했을까? 단순한 보존 본능이 아니었다. **기록은 처음부터 권력의 언어였다.** 무엇을 기록하느냐는 무엇을 통제하느냐와 같은 말이었다.

고대 메소포타미아에서 가장 먼저 체계적으로 기록된 것은 시나 철학이 아니었다. **보리의 수량, 노동자의 일수, 세금의 납부 여부**였다. 수메르의 점토판에 새겨진 쐐기문자 기록 중 상당수는 신전 창고의 재고 목록이다. 문자는 신을 찬양하기 위해 발명된 것이 아니라, 곡식을 세기 위해 발명된 것에 가까웠다.

| 📌 **읽을거리 — 지식의 집적은 곧 지식의 독점이었다** |
| :---- |
| 기원전 3세기 **알렉산드리아 도서관**의 목표는 순수한 학문적 열정인 동시에, 프톨레마이오스 왕조가 헬레니즘 세계의 지적 중심지로 군림하려는 정치적 기획이기도 했다. 항구에 입항하는 모든 배를 수색해 책을 빌려 필사한 뒤 원본을 돌려주지 않고 도서관에 보관했다는 기록도 전해진다. <br>18세기 청나라 건륭제가 편찬한 **사고전서(四庫全書)**도 표면적으로는 문화 보존 사업이었지만, 그 이면에는 제국의 이념에 맞지 않는 서적을 골라내고 사상을 통제하려는 목적이 함께 있었다. 수록 과정에서 수천 종의 서적이 수정되거나 삭제되었다. **무엇을 기록에 남기느냐는 곧 무엇을 역사로 만드느냐의 문제였다.** |

2000년대 초 미국 의회도서관의 인쇄 장서를 디지털 텍스트로 환산하면 약 10 TB 수준이라는 추정이 제시된 바 있다. 100 GB와 10 TB의 차이는 100배 이상이다. 불과 몇 세기 사이에 인류가 축적한 텍스트 데이터의 양이 기하급수적으로 팽창했음을 보여 준다.

중요한 것은 양의 증가만이 아니다. **데이터가 많아질수록 ‘정리·검색·분석·시각화’의 기술이 함께 발전해야 한다.** 데이터는 모아 두는 순간부터 관리의 문제가 된다.

### 3.2 농사와 세금, 그리고 국가 운영의 데이터

우리 역사에서도 체계적인 데이터 행정의 사례를 찾을 수 있다.

![][조선시대_토지대장]

조선 시대의 **양안(量案, 토지대장)**은 국가 자산을 수치화한 대표적 기록이다. 토지 면적, 소유자, 세금 부과 기준이 체계적으로 정리되었다. 1719년 숙종 대의 양전(量田) 사업은 전국 단위 토지 조사 사업이었다.

또 하나의 상징적인 기록 장치는 **측우기**였다. 1441년 세종 대(문종 시기 완성)에 제작된 측우기는 강우량을 계량화한 **세계 최초의 표준화된 강수 측정기**이다.

> 여러분은 조선 시대 강수량을 측정하던 ‘측우기’는 누가 만들었을까?

아마 많은 사람이 조선 최고의 과학자 **장영실**을 떠올릴 것이다. 실제로 장영실은 천문 관측기기와 자격루 등 여러 과학기술 제작에 참여한 인물이다. 그러나 기록에 따르면, 1441년(세종 23년) 측우기 제작을 직접 주도한 인물은 세종의 아들, 훗날 왕이 되는 **문종**이었다. 문종은 29년을 세자로 지내면서 세종을 도와 과학 발전에 기여했고, 정작 재위 기간은 3년밖에 되지 않았다. 『세종실록』에는 문종이 강우량을 정확히 측정할 기구 제작을 건의하고 추진한 사실이 명확히 기록되어 있다.

#### 한 나라의 왕세자가 왜 ‘빗물받이 통’에 진심이었을까

그 답은 조선이라는 국가의 구조에 있다. 조선은 농업을 기반으로 한 전형적인 농경 국가였다. 세금은 대부분 곡물로 거두어들였고, 국가 재정은 곧 농사의 성패에 달려 있었다. 비가 얼마나 내렸는지는 단순한 자연 현상이 아니라 **국가의 세수와 직결되는 핵심 변수**였다. 강수량은 그 시대의 가장 중요한 ‘데이터’였다.

측우기가 등장하기 전, 사람들은 비가 그치면 직접 땅을 파서 흙이 얼마나 젖었는지를 보고 강수량을 가늠했다. 그러나 지역마다 토양의 성질이 달랐고, 땅을 파는 깊이도 일정하지 않았다. 이는 주관적 판단에 의존한 측정 방식이었다. 동일한 비가 내려도 어떤 지역은 “많이 왔다”고 기록하고, 다른 지역은 “보통이다”라고 기록할 수 있었다. **객관적이고 표준화된 데이터가 없었던 것이다.**

문종은 이러한 오류를 해결하고자 했다. 1441년, 일정한 규격의 원통형 그릇을 이용해 빗물을 직접 받아 높이를 재는 장치가 제작된다. 이것이 바로 측우기다. 조선은 이 장치를 중앙뿐 아니라 지방에도 설치하여 강우량을 계량화했다. 기록에 따르면 전국 주요 지역에 측우기 관측망이 운영되었으며, 수치는 실록과 각종 관청 문서에 남겨졌다.

이 강수량 데이터는 다음과 같은 행정 영역에 활용되었다.

- 지역별 농사 작황 예측
- 가뭄·홍수 대비 정책 수립
- 구휼미(구제 곡물) 사전 준비
- 수리시설 관리
- 장기적인 기후 경향 파악

그러나 그 모든 활용의 중심에는 결국 **하나의 목표**가 있었다. 바로 **합리적이고 공정한 세금 징수**였다. 비가 부족해 수확량이 줄어든 지역에 동일한 세금을 부과한다면 백성의 삶은 붕괴된다. 반대로 풍년 지역에 적정한 세금을 걷지 못하면 국가 재정이 약해진다. 강수량이라는 객관적 데이터를 확보함으로써, 조선은 ‘감(感)’이 아니라 ‘기록’을 근거로 세율을 조정할 수 있었다.

측우기는 단순한 과학기구가 아니었다. **국가 재정의 기반을 정밀하게 측정하기 위한 장치**였다. 어쩌면 문종은 이미 알고 있었는지도 모른다. **정확한 데이터가 곧 공정한 통치의 시작**이라는 사실을. 조선의 강우 기록은 오늘날에도 기후 연구 자료로 활용되고 있다. 과거의 기록은 당시의 행정을 넘어, 현대 과학의 입력 데이터로 재해석된다. **기록은 시대를 넘어 살아남는다.**

---

### 3.3 과학적 발견의 기반: 데이터를 믿은 사람들

16세기 유럽, 사람들은 여전히 “지구가 우주의 중심”이라고 믿고 있었다. 태양과 별, 행성들이 지구를 중심으로 완벽한 원을 그리며 돈다는 ‘천동설’이 수세기 동안 정설이었다. 그런데 한 사람이 이 질서에 의문을 품었다. 덴마크의 천문학자 **튀코 브라헤(Tycho Brahe, 1546~1601)**였다.

튀코는 망원경이 발명되기 이전 시대의 인물이다. 그는 거대한 사분의(四分儀)와 육분의 등 정밀한 관측 장비를 직접 설계·제작하고, 전용 관측소 **우라니보르(Uraniborg)**를 세워 밤하늘을 체계적으로 기록했다. 그의 업적의 핵심은 ‘뛰어난 시력’이 아니라, **정밀한 기기와 반복 관측, 그리고 철저한 수치 기록**에 있었다. 단순히 별을 바라본 것이 아니라 날짜·시간·천체의 위치 각도, 반복 측정, 오차 비교를 통해 방대한 데이터를 축적했다.

| 📌 **읽을거리 — SN 1572: 하늘도 변한다는 사실을 데이터로 증명하다** |
| :---- |
| 1572년 11월 11일, 브라헤는 카시오페이아자리에서 이전에는 존재하지 않던 매우 밝은 별을 발견했다. 이는 오늘날 ‘**SN 1572**’로 불리는 초신성이었다. 그는 이 현상을 약 1년 반 동안 관측하며 밝기의 변화와 위치를 기록했다. 이 별은 다른 별들에 비해 움직이지 않았고, 점차 희미해졌다. 그는 이를 《De Nova Stella》(새로운 별에 대하여, 1573)에서 발표하며, **‘하늘은 변하지 않는 완전한 영역’이라는 아리스토텔레스적 우주관에 도전**했다. <br>그의 관측 오차는 당시 기준으로 약 1분(arcminute) 수준으로 매우 정밀했다. |

이후 튀코는 특히 화성의 위치를 수년간 정밀하게 관측했다. 이 방대한 화성 데이터는 제자 **요하네스 케플러**에게 전달되었다. 케플러는 기존의 원 궤도 가설에 데이터를 대입했으나 약 8분(arcminute)의 오차가 발생했다. 그는 이 작은 오차를 무시하지 않았다. 그 결과, 행성의 궤도는 원이 아니라 **타원**이라는 결론에 도달하였다. 이것이 바로 **케플러의 제1법칙**이다.

튀코는 지구 중심과 태양 중심을 절충한 ‘티코 체계’를 제안했지만, 그의 정밀한 관측 데이터는 결국 **코페르니쿠스의 태양 중심설을 수학적으로 정교화**하는 데 결정적인 역할을 했다. 이후 뉴턴의 만유인력 법칙으로 이어지며 과학혁명의 토대가 형성되었다.

인류가 천동설의 한계를 넘어설 수 있었던 배경에는, 망원경도 없던 시대에 이루어진 치밀한 관측과 기록이 있었다. **단순한 수치 기록은 결국 우주의 질서를 다시 쓰는 열쇠가 되었다.**

### 3.4 기록되는 사람들과 국가 역량의 계산

![][image2]

이 그림은 16세기 네덜란드 화가 **피터르 브뤼헐(Pieter Bruegel the Elder)**의 《베들레헴의 인구조사》(1566)이다. 눈 덮인 마을 광장에 사람들이 모여들고 있다. 가운데 나귀를 타고 있는 여인은 산달이 가까운 성모 마리아이며, 나귀를 끄는 이는 요셉이다. 이 장면은 누가복음 2장에 등장하는 ‘아우구스투스 황제의 인구조사 명령’을 바탕으로 한다. 요셉과 마리아도 인구조사에 참여하러 가는 듯이 보인다.

브뤼헐은 성서 속 팔레스타인을 그리지 않았다. 그는 16세기 플랑드르의 겨울 마을 풍경 속에 성서 이야기를 배치했다. 그림 속 건물은 여인숙으로, 지붕 아래 동그란 화환을 걸어놓아 여인숙임을 표시했다. 외벽에는 합스부르크 왕가를 상징하는 **쌍두독수리 문장**이 새겨져 있다. 이는 당시 네덜란드 지역이 스페인 합스부르크 왕가의 지배를 받고 있었음을 암시한다. 건물 앞에서는 몇몇 관리가 책상에 앉아 사람들의 이름을 기록하고 있다. 이들은 인구 등록을 담당하는 관리로 해석된다. 인구 등록은 단순한 행정 절차가 아니라 **세금 부과와 국가 통제의 기초**였다. 많은 미술사학자는 이 그림을 당시 합스부르크 통치 아래 강화되던 과세 제도와 행정 통제에 대한 은유적 비판으로 해석한다. 성서의 인구조사를 빌려 현실의 세금 행정을 비추어 본 것이다.

#### 인구는 곧 국가의 동원 가능 자원이었다

고대 로마에서 인구조사는 국가 운영의 핵심 제도였다. 시민은 자신의 재산과 가족을 등록해야 했으며, 이는 곧 세금과 군역의 기준이 되었다. 국가가 인구를 기록하는 이유는 분명했다.

- **세금**을 얼마나 걷을 수 있는가?
- **병력**을 얼마나 동원할 수 있는가?
- **전쟁**을 얼마나 오래 지속할 수 있는가?

전쟁은 단순히 무기의 싸움이 아니다. 병사를 유지할 식량, 세금으로 확보한 재정, 노동력을 제공하는 인구 구조가 있어야 지속된다. 따라서 인구조사는 단순한 행정 통계가 아니라 **국방력 그 자체**와 같았다.

### 3.5 데이터에서 권력으로, 그리고 시각화로

측우기는 강수량을 기록하여 세금을 공정하게 만들었고, 브라헤의 관측은 우주관을 바꾸었으며, 인구조사는 국가의 힘을 계산하고 합리적인 전쟁 설계를 가능하게 했다. 아주 오래전부터 사람들은 정보를 취합하여 기록된 숫자를 근거로 통계와 판단, 그리고 예측을 했다. **데이터는 정보이고, 정보는 곧 권력의 도구가 되었다.**

그런데 여기서 한 가지 문제가 생긴다. 데이터가 많아질수록 **그것을 읽는 것이 점점 어려워진다**는 점이다. 측우기의 강수량은 몇 개의 숫자로 기록할 수 있었다. 그러나 전국 수백 개 관측소의 수십 년치 강수 기록, 로마 전역의 수백만 인구 데이터, 브라헤가 20년 동안 쌓은 화성 관측값은 이미 인간이 눈으로 읽어낼 수 있는 범위를 훨씬 넘어서 있었다.

> 숫자는 충분했다. 그러나 숫자만으로는 **패턴이 보이지 않았다.**

인류는 결국 데이터를 ‘보이게’ 만드는 새로운 방법을 찾아야 했다. 수치를 그림으로, 목록을 지도로, 시간을 선으로 바꾸는 기술 — **데이터 시각화의 역사는 바로 이 필요에서 시작된다.** 4장에서는 숫자를 눈에 보이는 언어로 바꾼 선구자들의 이야기를 살펴본다.

### 4.1 데이터에서 인사이트로: 시각화의 필요성

앞선 장에서 우리는 인류가 얼마나 집요하게 데이터를 수집하고 기록해 왔는지를 살펴보았다. 측우기는 비를 숫자로 남겼고, 인구조사는 사람을 목록으로 만들었으며, 천문학자들은 별의 위치를 좌표로 기록하였다. 기록은 축적되었고, 국가는 점점 더 많은 숫자를 손에 쥐게 되었다.

그러나 문명이 발전하고 데이터가 폭발적으로 증가하면서 인류는 또 다른 문제에 직면했다. 바로 **인간 인지 능력의 한계**였다. 수만 줄로 이루어진 엑셀 표를 떠올려 보자. 사망자 명단, 기온 기록, 인구 통계, 세금 장부. 숫자는 정확하다. 틀린 값은 없다. 그런데 그 표를 처음부터 끝까지 읽어 내려가며 우리는 묻게 된다.

> “그래서, 무엇이 문제인가?”
> “어디에서 변화가 시작되었는가?”
> “무엇이 원인인가?”

숫자는 충분하지만, 패턴은 보이지 않는다. 인간의 뇌는 복잡한 계산을 빠르게 수행하도록 진화하지 않았다. 대신 우리는 **색의 대비, 점의 밀집, 선의 기울기**와 같은 시각적 패턴을 즉각적으로 인식하는 데 훨씬 뛰어나다. 긴 숫자 목록보다, 점이 한쪽에 몰려 있는 그림을 보는 순간 우리는 더 빠르게 의미를 파악한다. 이 인지적 특성을 활용하기 위해 등장한 것이 바로 **데이터 시각화(Data Visualization)**다.

인지과학자 **스튜어트 카드(Stuart Card)**는 시각화를 “마음 외부의 자원을 활용하여 인간의 인지 능력을 증폭시키는 과정”이라고 정의했다. 다시 말해, 시각화는 데이터를 예쁘게 꾸미는 그림이 아니라, 우리 뇌가 가장 강력하게 작동하는 방식을 활용하는 **인지적 도구(Cognitive Tool)**다. 점·선·면·색상은 단순한 디자인 요소가 아니다. **숫자를 계산하지 않고도 관계를 이해하게 만드는 장치**다. 시각화는 데이터의 양을 줄이는 것이 아니라, 이해의 속도를 높이는 기술이다.

#### 데이터에서 지혜로: DIKW 피라미드

시각화를 이해하기 위해서는 먼저 데이터가 어떻게 가치를 획득하는지 알아야 한다. 정보학에서는 이 과정을 **DIKW 피라미드**로 설명한다.

| 단계 | 정의 | 예시 |
| :--- | :--- | :--- |
| **D — Data (데이터)** | 단순한 수치의 나열 | “37.5”, “102”, “0” |
| **I — Information (정보)** | 맥락이 붙은 데이터 | “오늘 오전 서울 기온 37.5도” |
| **K — Knowledge (지식)** | 정보 속에서 발견한 패턴 | “기온이 35도를 넘으면 온열 환자가 급증한다” |
| **W — Wisdom (지혜)** | 그 패턴을 바탕으로 한 의사결정 | “폭염 예보 시 냉방 취약 계층에 선제 지원을 시행한다” |

이 상승 과정에서 가장 어려운 단계는 **‘정보에서 지식으로’** 넘어가는 순간이다. 흩어져 있는 숫자 속에서 규칙을 발견해야 하기 때문이다. 매일의 기온을 숫자로만 기록하면 그것은 데이터에 머문다. 월별로 정리하면 정보가 된다. 하지만 이를 그래프로 그려 보는 순간, **선이 점점 가파르게 올라가는 장면**이 눈에 들어온다. 그때 우리는 깨닫는다. “기온이 상승하고 있다.”

시각화는 바로 이 도약을 가능하게 한다. 복잡한 통계 수식을 몰라도, 한 장의 그래프가 패턴을 보여 준다. **결국 시각화란 보이지 않던 관계를 드러내는 기술이다.**

19세기 산업화와 도시화가 급속히 진행되면서, 인구·질병·사망·범죄·교통·무역 데이터가 폭증했다. 표로는 한계가 있었다. 숫자를 이해하기 위해 숫자를 넘어서는 표현 방식이 필요해졌다. 그리고 바로 그 지점에서, **한 장의 지도가 도시를 구했다.**

### 4.2 데이터에서 인과로: 공간 시각화의 혁명 (존 스노우)

#### 산업혁명이 만든 도시, 그리고 질병의 조건

18세기 후반 영국에서 시작된 1차 산업혁명은 인류의 생활 방식을 근본적으로 뒤바꾸어 놓았다. 증기기관과 방직 공장, 철도 산업이 급속도로 확산되면서 사람들은 일자리를 찾아 농촌을 떠나 도시로 몰려들었다. 영국의 심장 런던은 1800년 약 100만 명이던 인구가 1850년대에 이르러 **250만 명을 넘어설** 정도로 급격하게 팽창했다.

문제는 도시의 무분별한 확장 속도를 위생 인프라의 발전이 전혀 따라가지 못했다는 점이다. 당시 런던의 주요 교통수단이었던 수천 마리의 말들이 배출하는 오물이 거리 곳곳에 산더미처럼 쌓여 갔다. 가정집에는 현대적인 하수도 시설이 전무했고, 생활 폐수와 오물은 길거리의 개방된 배수구를 따라 속수무책으로 흘러갔다. 심지어 인분을 통에 담아 거리에 그대로 내다 버리는 관행마저 남아 있었다.

비가 내리는 날이면 상황은 더욱 끔찍해졌다. 거리의 오물들은 빗물과 뒤섞여 런던을 가로지르는 **템스강**으로 고스란히 유입되었다. 비극의 씨앗은 바로 이 템스강이 단순한 하천이 아니라 런던 시민들의 **‘주요 식수 공급원’**이었다는 사실에 있었다. 시민들은 집 근처 공공 펌프에서 물을 길어 마셨지만, 그 물이 어디에서 흘러와 어떤 오염 경로를 거쳤는지에 대한 과학적 이해는 전무한 상태였다.

| 📌 **읽을거리 — 산업혁명과 대기 오염** |
| :---- |
| 도시의 문제는 수질 오염에만 국한되지 않았다. 공장 굴뚝에서 쏟아져 나오는 석탄 연소 가스는 런던 하늘을 뒤덮었다. 석탄은 산업혁명의 핵심 에너지원이었지만, 대량 연소 과정에서 **황산화물과 미세한 탄소 입자**가 발생했다. 이로 인해 런던은 짙은 연무에 자주 휩싸였고, 19세기 중반부터 이미 런던의 ‘**스모그(smog)**’ 현상은 심각한 사회 문제로 인식되기 시작하였다. (20세기 중반의 대형 스모그 사건은 훨씬 후대의 일이지만, 산업혁명 시기에도 대기 오염은 구조적으로 존재하였다.) <br>썩은 물·동물 사체·하수·석탄 연기가 뒤섞인 공기는 사람들로 하여금 ‘질병이 나쁜 공기에서 비롯된다’고 믿게 만들기에 충분했다. |

#### 콜레라, ‘냄새의 병’이라 불리다

콜레라는 19세기 초 인도 벵골 지역에서 시작되어 전 세계로 확산된 급성 장관 감염병이다. 오염된 물을 통해 전파되며, 극심한 설사와 구토를 동반하고 급격한 탈수로 이어진다. 치료 기술이 미비하던 당시에는 감염 후 수 시간 내에 사망하는 경우도 드물지 않았다.

그러나 1850년대는 아직 세균학이 확립되기 전이었다. 루이 파스퇴르의 세균설이 의학계에 자리 잡기 이전이었고, 많은 의사는 악취가 질병을 유발한다는 **미아즈마(Miasma) 이론**을 신뢰하고 있었다. 실제로 악취가 심한 지역에서 질병이 자주 발생했기 때문에, 그 가설은 겉보기에 상당히 설득력이 있었다.

1858년 발생한 ‘**대악취(Great Stink)**’ 사건은 당시 환경이 얼마나 심각했는지를 보여 준다. 여름철 템스강의 수위가 낮아지면서 오염된 퇴적물이 노출되었고, 의회는 악취 때문에 창문에 소독약을 적신 커튼을 달아야 할 정도였다. 이러한 환경 속에서 콜레라는 자연스럽게 ‘냄새의 병’으로 이해되었다.

| 📌 **읽을거리 — 세균을 몰랐던 시대의 의학적 믿음** |
| :---- |
| **미아즈마(Miasma)**는 고대 그리스어로 ‘오염’이나 ‘나쁜 공기’를 뜻한다. 현미경이 발명되고 ‘세균(Germ)’의 존재가 과학적으로 증명되기 전까지, 19세기 의학계를 지배했던 가장 강력한 정설은 “부패한 쓰레기나 시체에서 발생하는 악취(나쁜 공기)를 들이마시면 병에 걸린다”는 **미아즈마 이론(장기설, 瘴氣說)**이었다. <br>당시 사람들은 바보가 아니었다. 산업혁명기 런던의 빈민가나 오물이 쌓인 거리는 코를 찌르는 악취가 진동했고, 공교롭게도 그런 지역에서 콜레라나 장티푸스 환자가 집중적으로 발생했기 때문이다. 사람들은 데이터의 ‘원인(오염된 식수)’과 ‘결과(콜레라)’를 정확히 연결하지 못하고, 눈에 띄는 현상인 ‘악취’를 원인으로 착각하는 오류를 범했다. 그래서 콜레라를 막기 위해 창문을 굳게 닫고, 거리의 냄새를 덮기 위해 식초나 태운 화약 냄새를 피우는 엉뚱한 대처를 하곤 했다. <br>유명한 질병인 **말라리아(Malaria)** 역시 이탈리아어로 ‘나쁜(Mal) 공기(Aria)’라는 뜻에서 유래한 이름이다. |

#### 명단에서 지도로: 패턴을 그려 내다

1854년 8월, 런던 소호 지역에서 콜레라가 폭발적으로 확산되었다. 단 며칠 사이에 수십 명이 사망했고, 약 열흘 동안 500~600명 이상이 목숨을 잃은 것으로 기록된다. 의사 **존 스노우(John Snow)**는 진료 현장에서 환자들을 직접 보며 이상함을 느꼈다. 병은 특정 지역에서 유독 집중적으로 발생하고 있었다. 좁은 거리 하나를 사이에 두고 생존과 사망이 갈렸다.

> 그는 질문했다. “공기가 원인이라면 왜 이 거리에서만 이렇게 집중되는가?”

존 스노우는 콜레라가 공기가 아닌 **‘오염된 물’**을 통해 전염된다고 강하게 의심했다. 그러나 직관적인 주장만으로는 견고한 기존의 의학적 통념을 뒤집을 수 없었다. 그에게는 가설을 증명할 객관적인 ‘증거’가 필요했다. 그는 가장 먼저 사망자들의 주소를 일일이 추적하여 데이터를 수집했다. 당시 통계 담당자 **윌리엄 파(William Farr)**의 사망 기록도 참고했다. 이름·나이·주소·사망 원인. 숫자는 충분했다. 그러나 그는 그 명단을 읽다가 멈췄다.

> “이 숫자는 다른 방식으로 보여야 한다.”

그는 소호 지구의 지도를 펼쳐 놓고, **사망자 한 명당 검은 막대 하나**를 표시하기 시작했다. 데이터가 지도 위에 쌓여 가자, 눈으로는 볼 수 없던 놀라운 장면이 수면 위로 떠올랐다. 사망자들의 위치가 특정 펌프, 즉 ‘**브로드 스트리트(Broad Street) 펌프**’ 주변으로 빽빽하게 군집(Clustering)되어 있었던 것이다. 펌프에서 몇 블록만 벗어나도 사망자는 급격히 줄어들었다.

만약 당대의 믿음처럼 ‘공기’가 원인이었다면 사망자는 바람을 타고 넓고 무작위하게 퍼졌어야 했다. 그러나 스노우의 지도는 **피해가 특정한 수원(水源)을 중심으로 동심원을 그리며 확산**되었음을 명확히 지목하고 있었다.

#### 이상치(Outlier)가 가설을 증명하다

더 나아가 스노우는 이 지도를 바탕으로 **예외적인 데이터(이상치)**를 역추적하여 자신의 가설을 더욱 단단하게 다졌다.

- **맥주 양조장의 생존자들** — 브로드 스트리트 펌프 바로 인근에 있던 맥주 양조장에서는 사망자가 거의 발생하지 않았다. 조사 결과, 그곳의 노동자들은 갈증을 달래기 위해 펌프 물 대신 **끓이는 과정을 거친 ‘맥주’**를 마셨기 때문이었다.
- **멀리 떨어진 햄프스턴의 사망자** — 펌프와 멀리 떨어진 안전한 지역에 살던 한 부인이 콜레라로 사망했다. 스노우의 조사 결과, 과거 소호에 살았던 이 부인은 **브로드 스트리트 펌프 물의 맛을 특별히 좋아해 매일 그 물을 배달시켜 마셨다**는 사실이 밝혀졌다.

#### 펌프 손잡이의 제거와 도시의 변화

결정적인 데이터의 인과관계를 확보한 존 스노우는 즉시 지역 행정위원회를 찾아가 브로드 스트리트 펌프의 **손잡이를 제거할 것**을 강력히 요청했다. 손잡이가 제거되어 문제의 물 공급이 차단되자, 걷잡을 수 없던 콜레라의 유행은 빠르게 잦아들었다. (비록 유행이 이미 정점을 지나 자연 감소 국면에 접어들고 있었다는 후대의 견해도 있으나, 그의 선제적 조치가 결정적이었음은 부인할 수 없다.)

이 사건은 영국 사회에 엄청난 충격을 주었고, 대대적인 도시 위생 개혁을 촉발했다. 토목기사 **조지프 바잘게트(Joseph Bazalgette)**의 설계로 1860년대에 건설된 거대한 런던 지하 하수도 시스템은 오늘날 현대 도시 하수도의 훌륭한 기초가 되었다.

> **시각화는 데이터를 단지 예쁘게 설명한 것이 아니라, 데이터 스스로가 진실을 말하게 만든 강력한 도구였다.**

존 스노우의 업적은 단순히 한 지역의 전염병을 통제한 일화로 끝나지 않는다. 그는 ‘사망자 명단(Data)’을 지도 위에 배치함으로써, 무미건조한 숫자들을 **‘공간적 관계(Information)’**로 변환해 냈다. 사망자 명단과 주소 기록이라는 데이터는 이미 행정관청의 장부 속에 존재하고 있었다. 그러나 그 파편화된 데이터가 시각적 지도라는 ‘보이는 구조’로 재배치되는 순간, 원인은 더 이상 막연한 가설이 아니라 명백한 **‘패턴(Pattern)’**이 되었다.

이 사건은 의학계에서 현대 **역학(Epidemiology)**이 탄생하는 위대한 출발점이 되었으며, 국가의 공중보건 정책이 막연한 추측에서 ‘**데이터 기반의 의사결정**’으로 전환되는 결정적인 계기가 되었다.

### 4.3 통계에서 정책으로: 설득의 시각화 (나이팅게일)

존 스노우가 런던 소호에서 콜레라 지도를 그리고 있던 1854년 무렵, 흑해 북쪽 크림반도에서는 또 다른 위기가 전개되고 있었다. 그것이 바로 **크림전쟁(Crimean War, 1853~1856)**이다.

이 전쟁은 단순한 지역 분쟁이 아니었다. 당시 유럽은 오스만 제국의 쇠퇴를 둘러싸고 복잡한 세력 균형 경쟁을 벌이고 있었다. 러시아 제국은 오스만 영토와 흑해·지중해로의 진출을 확대하려 했고, 이는 영국과 프랑스의 해상 패권과 무역 항로, 특히 인도 항로에 위협이 될 수 있었다. 결국 러시아와 오스만 제국 간의 갈등은 영국과 프랑스가 참전하면서 국제전으로 확대되었고, 전장은 오늘날 우크라이나 남부에 해당하는 크림반도 일대였다.

영국은 해군력과 산업력을 바탕으로 전쟁에 참여했지만, **장거리 원정 전쟁에 대한 병참·의료 준비는 매우 미흡**한 상태였다.

#### 전투보다 더 많은 병사를 죽인 것

1854년, 영국군의 주요 야전 병원은 당시 오스만 제국 영토였던 **스쿠타리(Scutari, 현재 터키 이스탄불의 우스퀴다르 지역)**에 설치되었다. 이곳으로 수천 명의 부상병과 환자가 몰려들었다. 병원 환경은 참혹했다. 하수 시설은 제대로 작동하지 않았고, 환기와 청소는 체계적으로 이루어지지 않았다. 오염된 물과 과밀한 병상, 위생 관리 부재는 감염병 확산의 조건을 완벽하게 갖추고 있었다.

당시 군 수뇌부와 대중은 전쟁에서 병사들이 죽는 가장 큰 원인은 당연히 ‘적군의 총칼’이라고 믿었다. 그러나 실제 기록은 전혀 다른 현실을 보여 주고 있었다. 크림전쟁 기간 영국군 사망자의 상당수는 전투가 아니라 **감염병으로 인한 것**이었다. 월별 통계 자료를 보면 특정 시기에는 전투 사망보다 콜레라·이질·장티푸스 등 전염병 사망이 훨씬 많았다. 일부 분석에서는 초기 병원 사망률이 **40%에 육박**한 것으로 추정되기도 한다. 적보다 위생이 더 많은 병사를 죽이고 있었던 것이다.

1854년, **플로렌스 나이팅게일(Florence Nightingale, 1820~1910)**은 38명의 간호사와 함께 스쿠타리로 파견되었다. 병원의 실태를 직접 목격한 그녀는 단순한 감정적 분노에 머물지 않았다. 그녀는 데이터를 모으기 시작했다.

- 월별 사망자 수
- 사망 원인의 구분
- 병원 환경 개선 이후의 변화
- 계절에 따른 사망률 변동

그녀는 **간호사이자 통계학적 사고를 갖춘 개혁가**였다. 전투로 인한 사망보다 병원 내 감염병으로 인한 사망이 훨씬 많았다. 그러나 이 사실을 단순한 통계 표로 제출하는 것만으로는 정부를 움직이기 어려웠다.

#### 로즈 다이어그램: 숫자를 설득의 무기로 바꾸다

나이팅게일은 복잡한 표 대신 새로운 표현 방식을 선택했다. 그녀는 **12개월을 원의 12개 부채꼴**로 나누고, 각 조각의 면적으로 사망자 수를 나타냈다. 그리고 사망 원인에 따라 색을 달리했다.

- **푸른색(또는 회색 계열)** — 예방 가능한 전염병 사망
- **붉은색** — 전투 사망
- **검은색** — 기타 원인

완성된 그래프는 충격적이었다. 붉은색(전투 사망) 영역은 중심에 아주 작게 몰려 있는 반면, **푸른색(비위생으로 인한 전염병 사망) 영역은 화면의 대부분을 거대하게 뒤덮고 있었다.** 마치 피어나는 장미꽃의 형태를 닮았다 하여 **로즈 다이어그램(Rose Diagram)**이라 불리게 된 이 그래프 한 장은, “우리 군인들을 죽이는 것은 적군의 총알이 아니라 아군의 불결한 병원이다”라는 메시지를 묵직하게 뿜어내고 있었다.

나이팅게일은 이 시각화 자료를 **빅토리아 여왕과 영국 의회, 그리고 군 수뇌부**에게 보고했다. 결과는 즉각적이었다. 통계 표를 볼 때는 지루해하던 정치인들이 직관적인 그래프 앞에서는 변명할 여지 없이 문제의 심각성을 인정하게 된 것이다. 그래프의 압도적인 설득력에 힘입어 나이팅게일은 막대한 예산과 지원을 끌어내는 데 성공했다. 병원의 하수구를 청소하고 환기 시설을 개선하며, 깨끗한 물과 건조한 환경을 유지하는 대대적인 위생 개혁 정책이 즉각 시행되었다. 그 결과, **42%에 달하던 병원 내 사망률은 불과 6개월 만에 2%대로 급감**하는 기적 같은 성과를 이뤄 냈다.

> **숫자는 설명이지만, 그래프는 설득이다.**

나이팅게일의 로즈 다이어그램은 데이터 시각화가 단순한 ‘**설명(Explanatory Visualization)**’을 넘어, 사회적 합의를 이끌어내고 국가의 ‘정책 의사결정’을 바꾸는 가장 강력한 정치적·사회적 도구가 될 수 있음을 증명한 최초의 사례다.

데이터는 현실을 객관적으로 비추는 거울이지만, 그 데이터가 변화를 만들어 내기 위해서는 **대중과 결정권자의 마음을 움직일 수 있는 ‘전달력’**이 필수적이다. 현대 사회에서 복잡한 데이터를 시각화하여 대중에게 진실을 알리는 ‘**데이터 저널리즘(Data Journalism)**’의 기원 역시 바로 이 19세기 나이팅게일의 장미꽃 도표에서부터 피어났다고 할 수 있다.

---

이처럼 시각화란 단순히 숫자를 그림으로 예쁘게 바꾸는 기술이 아니다. 그것은 **보이지 않던 인과관계를 찾아내고**(존 스노우), **타인을 논리적으로 설득하여 세상을 더 나은 방향으로 바꾸어 내는**(플로렌스 나이팅게일) 가장 위대한 소통의 마법이다.

### 📚 2부 정리하기

- 존 스노우는 시각화로 **인과관계**를 드러냈고, 나이팅게일은 시각화로 **정책**을 바꿨다.

### 5.1 산업혁명과 인간 역할의 변화

인류는 산업혁명의 발전과 함께 **노동의 형태와 삶의 방식**이 급격히 변화해 왔다. 산업혁명을 한 문장으로 정리하면 “**인간의 역할이 계속 바뀌어 온 과정**”이라고 할 수 있다.

| 구분 | 시기 | 핵심 동력 | 인간의 역할 |
| :--- | :--- | :--- | :--- |
| **1차** | 18C 후반~ | 증기기관 | 단순 반복 노동, 공장의 작업자 |
| **2차** | 19C 후반~ | 전기·화학·대량생산 | 기계 조작·관리, 통신 활용 |
| **3차** | 20C 중반~ | 컴퓨터·자동화·인터넷 | 정보 처리, 컴퓨팅 사고 |
| **4차** | 21C~ | AI·빅데이터·IoT·초연결 | 데이터 해석, 판단 설계, 책임 |

1차 산업혁명은 **증기기관**을 통해 인간의 근력을 기계로 대체하며 인간을 육체노동에서 해방시켰다. 무거운 물건을 들고 나르던 일, 끝없이 같은 작업을 반복하던 일에서 사람은 조금씩 벗어났다. 그런데 흥미로운 점은, 육체노동에서 벗어난 인간이 거기서 멈추지 않았다는 사실이다. 몸이 자유로워지자 인간은 곧 또 다른 질문을 품게 된다.

> “이제는 몸뿐 아니라 **생각도** 기계가 대신해 줄 수는 없을까?”

2차 산업혁명은 전기·화학·석유·철강 등 새로운 에너지와 기술의 발전으로 생산과 효율을 향상시킨 시기였다. 특히 전기 신호를 활용한 통신이 발달하기 시작했다. 밤늦게도 일할 수 있게 되어 발전 속도는 더욱 빨라졌다. 통신·자동화·전화기·라디오·TV·대량생산이 잇달아 등장했다. 무엇보다 **전기는 켜짐(1)과 꺼짐(0)의 신호로 정보를 표현하는 방식**으로 이어져, 훗날 인공지능의 초기 개념에 영향을 주게 된다.

3차 산업혁명은 컴퓨터와 자동화 기술이 급속도로 발전한 시기다. 단순 육체노동이 아니라 **컴퓨터를 다루고 정보를 처리할 수 있는 능력**이 필수가 된 시대다. 4차 산업혁명에 들어서면서는 인공지능·빅데이터·사물인터넷·초연결 사회가 사회 운영의 기본 조건이 되었다. 사회가 요구하는 역량 또한 달라졌다. 단순히 기술을 소비하는 것이 아니라, **데이터를 분석하고 활용하는 능력**과 **컴퓨팅 사고력**이 핵심이 되었다.

| 📌 **읽을거리 — 대항해 시대와 산업혁명의 밑거름** |
| :---- |
| 1차 산업혁명 이전, 영국은 엘리자베스 1세 여왕이 해적에게 약탈 허가증(사략 면허)을 내주어 스페인의 무적함대를 무찌르며 ‘해가 지지 않는 나라’로 성장하는 기반을 마련했다. 네덜란드는 최초의 주식회사인 ‘동인도 주식회사’를 만들어 먼 곳까지 항해해 식민지를 확장했다. 이때 네덜란드인 **하멜이 표류해 우리나라에 닿은 사건**도 같은 시대의 일이다. 네덜란드의 자본주의와 영국의 침략 전쟁은 물리학·수학을 발전시켰고, 이 모든 흐름이 결국 **산업혁명의 밑거름**이 되었다. |

### 5.2 ‘인간 컴퓨터’와 찰스 배비지: 사고의 기계화를 향한 첫걸음

오늘날 우리가 너무도 자연스럽게 사용하는 **‘컴퓨터(Computer)’**라는 단어는, 처음부터 기계를 뜻한 말이 아니었다. 이 단어는 원래 **‘계산을 전문적으로 수행하던 사람의 직업 명칭’**이었다. 과거의 ‘인간 컴퓨터’들은 천문 관측 데이터를 계산하고, 항해 경로를 예측하며, 포탄의 궤적처럼 복잡한 수식을 반복해서 계산하는 일을 맡았다. 즉, 컴퓨터는 처음부터 기계가 아니라 **인간의 사고와 계산 능력 그 자체를 가리키는 말**이었다.

하지만 인간의 사고는 완벽하지 않다. 아무리 숙련된 계산가라 하더라도 피로를 느끼고, 감정에 영향을 받으며, 같은 계산을 반복할수록 실수를 저지르기 쉽다. 계산 결과 하나가 과학적 발견이나 군사 전략, 국가 재정에까지 영향을 미치던 시대에는 이러한 실수가 결코 사소한 문제가 아니었다.

> “사람보다 더 정확하고, 지치지 않고, 항상 같은 결과를 내는 존재가 있다면 얼마나 좋을까?”

이러한 고민 속에서 19세기 영국의 수학자 **찰스 배비지(Charles Babbage)**가 등장한다. 배비지는 인간 사고의 한계와 계산 오류를 극복하기 위해 ‘**해석기관(Analytical Engine)**’이라는 기계적 장치를 고안했다. 이 장치는 단순히 계산을 빠르게 하기 위한 계산기가 아니었다. 사칙연산이 가능하고 50자리의 숫자를 1,000개까지 저장할 수 있도록 설계되었으며, 지금의 **중앙처리장치(CPU)** 역할을 하는 ‘**밀(mill)**’, **메모리** 역할을 하는 ‘**스토어(store)**’, 그리고 **출력 인쇄기**까지 갖추고 있었다. 배비지가 살아 있을 때 완성하지는 못했으나, 이 ‘해석기관’은 오늘날 우리가 사용하는 **컴퓨터의 기본 개념**이 되었다.

배비지가 기계를 만들고자 했던 이유는 분명하다. 인간보다 더 똑똑한 존재를 만들고 싶었던 것이 아니라, **인간 사고에서 반복적으로 발생하는 실수를 줄이고 싶었던 것**이다. 이는 인간의 사고를 부정한 시도가 아니라, **인간 사고의 약점을 정확히 인식하고 기술로 보완하려는 선택**이었다.

이 지점에서 인공지능 역사의 출발선이 드러난다. ‘기계는 생각할 수 있는가’라는 질문보다 먼저, **‘인간은 왜 자신의 사고를 기계에 맡기고 싶어 했는가’**라는 질문이 존재했던 것이다. 인공지능은 어느 날 갑자기 등장한 기술이 아니라, 인간이 스스로의 사고 한계를 자각하고 이를 외부로 확장하려는 오랜 욕망이 축적된 결과라고 할 수 있다. **반복적이고 규칙적인 판단은 기계에 맡기고, 인간은 의미를 해석하고 방향을 결정하는 역할로 이동하는 것** — 이 사고의 분업 구조가 이후 인공지능이 등장하고 발전하는 모든 과정의 밑바탕이 된다.

### 5.3 전쟁과 계산: 컴퓨터의 탄생 배경

기계가 인간의 근력을 대신해 주던 시대가 길어질수록, 또 하나의 한계가 분명해지기 시작했다. 기계는 힘든 일을 대신해 주었지만 **계산과 판단만큼은 여전히 인간의 몫**으로 남아 있었기 때문이다. 공장이 커지고, 철도가 확장되고, 국가 단위의 행정과 군사 작전이 복잡해질수록 다뤄야 할 숫자와 정보의 양은 급격히 늘어났다.

특히 전쟁은 이 한계를 가장 극단적으로 드러낸 환경이었다. 단순히 힘이 센 무기보다 **누가 더 빠르고 정확하게 계산하느냐**가 승패를 가르곤 했다. 포탄의 탄도 계산, 병력과 물자의 이동 경로, 암호화된 통신의 해독까지 — 전쟁의 모든 순간에는 수많은 계산과 판단이 뒤따랐다.

#### 2차 세계대전과 앨런 튜링

1939년~1945년에 이어진 **2차 세계대전**은 영국·소련·미국·중국 연합과 나치 독일·이탈리아·일본 제국이 맞붙은, 사망자 7,300만 명 이상의 가장 파괴적인 전쟁이었다. 전쟁의 승패를 가르는 주요한 요인 중 하나는 **정보**였다. 적군이 언제·어디로·얼마의 규모로 침공하는지 알 수 있다면 유리한 고지에서 전쟁을 치를 수 있었다.

독일은 **‘에니그마(Enigma)’**라는 암호 생성기를 사용했는데, 매일 암호 체계가 바뀌었고, 암호학자·체스 챔피언·수학자·언어학자 등 뛰어난 두뇌들도 하루 종일 암호 해독만 하다 하루를 보내기 일쑤였다. 이때 암호 해독에 참여한 **앨런 튜링(Alan Turing)**은 인간의 속도로는 암호 해독을 따라갈 수 없다고 판단하고, 거대한 암호 연산 기계 ‘**봄(Bombe)**’을 개발했다. 이 내용을 다룬 영화가 ⟪이미테이션 게임⟫이다. 이들의 활약으로 2차 세계대전이 최소 2년 이상 단축되었고 수천만 명의 목숨을 살렸다는 평가를 받는다.

종전 후 학교로 돌아간 튜링은 역사적인 논문 「Computing Machinery and Intelligence」를 발표한다. 논문은 다음과 같은 첫 문장으로 시작한다.

> **“Can machines think?” (기계는 생각할 수 있는가?)**

방에 컴퓨터와 인간을 각각 다른 방에 두고, 밖에서 질문을 했을 때 돌아오는 답변 두 개 중 어떤 것이 인간의 답변인지 분간하기 어렵다면 ‘기계도 생각할 수 있다’고 간주한다는 사고 실험이었다. 이것이 바로 **튜링 테스트(Turing Test)**, 즉 ‘이미테이션 게임’이다.

![][이미테이션게임]

| :---- |
| 튜링은 인간의 사고를 확장할 기계를 꿈꾸며 논문을 썼다. 하지만 그는 성소수자였고, 당시 영국에서 동성애는 불법이었다. 감옥에 갈 것인지 화학적 거세를 받을 것인지 선택해야 했고, 그는 컴퓨터 연구를 계속하기 위해 화학 요법을 선택했다. 그러나 그는 화학 요법의 고통을 끝내 견디지 못했고, **수백 년 동안 세상을 바꿀 질문 “Can machines think?”를 남기고 사라졌다.** |

#### 다트머스 회의: ‘인공지능’이라는 이름이 태어나다

1950년대는 2차 세계대전 이후 컴퓨터 기술이 발전하고, 기계가 다양한 문제를 해결할 수 있다는 가능성이 확장되는 시기였다. ‘기계가 학습 가능하며 문제를 해결할 수 있다’는 연구는 튜링 외에도 여러 컴퓨터 과학자·수학자 사이에서 활발히 논의되었다.

**1956년 7월~8월** 두 달간 미국 다트머스 대학에 수학·컴퓨터 과학 학자들이 모여 AI에 대한 아이디어와 연구 방향을 논의하고 ‘**인공지능(Artificial Intelligence)**’이라는 용어의 개념을 확립한 역사적인 회의를 열었다. 이 회의는 **존 매카시(John McCarthy)**와 **마빈 민스키(Marvin Minsky)**가 개최하였으며, 정보 이론과 전기공학을 연구한 **클로드 섀넌**, 최초의 어셈블리어를 작성한 **나다니엘 로체스터**, 최초의 자기 학습 체커 프로그램을 작성한 **아서 사뮤엘**, 인지과학자 **앨런 뉴웰**, 훗날 튜링상과 노벨경제학상을 수상한 **허버트 사이먼** 등 인공지능 발전에 큰 업적을 남긴 인물들이 대거 참석했다.

#### 기호주의의 시대

이 당시 인공지능은 논리연산자(∧·∨·¬·→·↔), 양화사(∀·∃), 상수·변수를 사용하는 **‘기호주의(Symbolic AI)’** 방식으로 접근했다. 인간의 사고와 지식을 기호로 표현하여 의미를 구성하고, **규칙에 의한 논리적 연산으로 결론을 도출**하는 방식이다. 이 시기 컴퓨터는 거대하지만 단순한 논리 회로와 기초 연산 능력만 가지고 있었기 때문에, 내용과 뜻이 분명한 규칙을 따르는 프로그램을 작성하는 데 적합했다. 전문가들은 인간의 지능이 특정 기호 체계에 따라 규칙적으로 작동한다고 보았고, 기계가 이를 모방하여 논리적 사고와 수학적 규칙을 기반으로 추론할 수 있도록 컴퓨터 프로그램으로 표현하려 했다.

---

### 5.4 AI의 발전: 기호주의에서 딥러닝, 그리고 생성형 AI까지

인공지능은 1950년대부터 시작되어, 초기에는 ‘A or B 정도’의 논리적 판단 수준에 머물렀다. 이후 사람이 기계에 정보를 주입시켜 학습을 시키는 방식으로 발전했고, 그 방식이 점차 진화하면서 컴퓨터가 **스스로 학습**하게 되었다. 학습하는 수준이 사람의 뇌신경처럼 복잡한 문제를 추론하고 판단할 수 있는 수준에 이르는 과정이 바로 **딥러닝(Deep Learning)**이다.

| 시대 | 패러다임 | 특징 |
| :--- | :--- | :--- |
| 1950~80년대 | **기호주의 / 규칙 기반** | 인간이 규칙을 입력 → 기계가 추론 |
| 1980~2000년대 | **머신러닝(통계 학습)** | 데이터에서 패턴을 학습 (예: 의사결정나무, SVM) |
| 2010년대~ | **딥러닝** | 인공신경망 다층화, 이미지·음성·언어 인식 비약적 발전 |
| 2020년대~ | **생성형 AI (LLM)** | GPT·Gemini·Claude 등, 인간 언어로 추론·창작 |

특히 4차 산업혁명 시대에 들어서면서 **딥러닝과 빅데이터** 기술이 인공지능을 비약적으로 발전시켰다. 방대한 데이터를 분석하고 학습하는 능력을 갖춘 인공지능은 이제 인간과 유사한 수준의 의사결정을 수행할 수 있게 되었다.

#### 인간의 역할은 어디로 가는가

처음에는 **힘을 쓰는 역할**, 그다음에는 **기계를 다루는 역할**, 그리고 이제는 **판단을 설계하는 역할**로 인간의 자리는 계속 이동하고 있다. 이는 일자리가 사라진다는 단순한 문제를 넘어, **인간이 어떤 역할을 수행해야 하는지에 대한 근본적인 질문**을 던진다.

> 처음에는 힘을 쓰는 역할, 그다음에는 기계를 다루는 역할, 그리고 이제는 **판단을 설계하는 역할**로.

이 변화는 ‘**인간이 무엇을 하던 존재였는가**’가 바뀌어 온 역사라고 할 수 있다. 인공지능과 함께 살아가는 시대, 우리에게 필요한 것은 기술 그 자체가 아니라 **그 기술을 어떻게 설계하고 사용할 것인가를 선택하는 인간의 판단**이다. 이것이 다음 6장에서 다룰 ‘인공지능 윤리’의 출발점이다.

### 6.1 4차 산업혁명, AI가 일상이 된 시대

인공지능 기술은 더 이상 미래의 가능성이나 일부 전문가의 연구 대상에 머무르지 않는다. 오늘날 인공지능은 **검색·추천·번역·음성 인식·이미지 분석**의 형태로 일상 전반에 깊숙이 자리 잡고 있으며, 개인의 선택과 사회의 운영 방식에 실질적인 영향을 미치고 있다. 이러한 변화는 단순히 기술이 발전했다는 사실보다, **기술이 인간의 삶과 사회 구조에 개입하는 방식이 달라졌다**는 점에서 중요하다.

인공지능이 빠르게 확산된 배경에는 두 가지 핵심 조건이 있다.

1. **디지털 환경의 확장** — 인터넷·스마트폰·플랫폼 서비스가 개인의 검색 기록, 이동 경로, 소비 패턴, 의사소통 방식을 지속적으로 데이터화한다.
2. **컴퓨팅 기술의 발전** — 고성능 연산 장치와 클라우드 인프라는 대규모 데이터를 빠르게 처리할 수 있는 환경을 제공했고, 이는 인공지능 모델의 성능 향상으로 이어졌다.

이러한 조건 속에서 인공지능은 단순한 규칙 기반 프로그램을 넘어, **패턴을 학습하고 미래의 가능성을 예측**하는 기술로 발전했다. 특히 딥러닝과 생성형 인공지능의 등장은 인공지능이 분석의 영역을 넘어 **창작과 판단**에 관여하는 단계로 진입했음을 보여 준다. 이로 인해 인공지능은 인간의 노동을 보조하는 도구를 넘어, **사회적 의사결정 과정에 영향을 미치는 기술**로 인식되기 시작했다.

생활 방식 또한 변화하고 있다. 공유 서비스와 플랫폼 기반 시스템은 편리함을 제공하지만, 동시에 **개인의 선택이 알고리즘에 의해 형성되는 구조**를 만든다. 의료·교통·금융·교육 분야에서 인공지능의 활용이 확대될수록, 기술의 효율성만큼이나 그 결과에 대한 사회적 책임이 중요해진다. 이 지점에서 인공지능은 기술의 문제가 아니라 **사회적·윤리적 문제**로 확장된다.

### 6.2 AI 윤리의 4가지 핵심 쟁점

AI 윤리는 기술이 충분히 발전한 이후에야 등장한 부수적 논의가 아니다. 인공지능이 사회적 의사결정에 관여하기 시작하면서 **필연적으로 제기된 문제의식**이다. 인공지능은 사람을 대신해 분류하고, 예측하며, 판단을 보조한다. 이 과정에서 기술의 결과는 개인의 기회·권리·삶의 방향에 직접적인 영향을 미친다.

중요한 점은 인공지능이 스스로 도덕적 판단을 내리는 존재가 아니라는 사실이다. 인공지능은 **데이터를 학습하고 목표 함수에 따라 결과를 산출할 뿐**, 그 결과가 공정한지 혹은 바람직한지를 판단하지 못한다. 따라서 AI 윤리는 ‘기계의 윤리성’을 묻는 개념이 아니라, **인공지능을 설계하고 사용하는 인간과 사회의 책임**을 묻는 윤리이다.

| 쟁점 | 핵심 질문 | 대표 사례 |
| :--- | :--- | :--- |
| **① 편향과 차별** | AI는 누구에게 불리한가? | 채용·신용 평가·얼굴 인식의 인종/성별 편향 |
| **② 책임의 분산** | 사고가 나면 누가 책임지는가? | 자율주행 사고, 알고리즘 추천의 결과 |
| **③ 설명 가능성·투명성** | 왜 그런 판단이 나왔는가? | 딥러닝 ‘블랙박스’ 문제, XAI |
| **④ 개인정보와 감시** | 데이터는 어디까지 수집·활용되는가? | CCTV·행동 로그·표적 광고 |

#### ① 편향과 차별

인공지능은 **과거의 데이터를 학습**하기 때문에, 데이터에 포함된 사회적 불균형과 차별 구조를 그대로 반영하거나 강화할 위험이 있다. 실제로 채용·신용 평가·얼굴 인식 기술 등에서 특정 집단에 불리한 결과가 나타난 사례들이 보고되어 왔다. 이러한 문제는 기술의 오류라기보다 **사회 구조가 데이터에 반영된 결과**라는 점에서 더욱 복합적이다.

#### ② 책임의 불분명성

인공지능이 관여한 결정에서 문제가 발생했을 때, 책임이 누구에게 있는지를 명확히 하기 어렵다. **알고리즘을 설계한 개발자, 데이터를 제공한 기관, 시스템을 운영한 조직, 결과를 활용한 사용자**가 분리되어 있기 때문이다. 이로 인해 인공지능은 **책임이 분산되는 구조**를 만들 수 있으며, 이는 사회적 신뢰를 약화시키는 요인이 된다.

#### ③ 설명 가능성과 투명성

현대 인공지능은 복잡한 구조를 가지며, 그 판단 과정을 인간이 직관적으로 이해하기 어렵다. 그러나 사회적 의사결정에 활용되는 시스템일수록 **‘왜 그런 결과가 나왔는지’**를 설명할 수 있어야 한다. **설명 가능성(Explainable AI, XAI)**은 단순한 기술적 요구가 아니라, 책임성과 신뢰를 가능하게 하는 윤리적 조건이다.

#### ④ 개인정보와 감시

인공지능은 대규모 데이터를 기반으로 작동하며, 이 데이터에는 개인의 사적인 정보가 포함되는 경우가 많다. **편의성과 안전을 이유로 수집된 데이터가 통제와 감시로 전환될 가능성**은 항상 존재하며, 이는 민주 사회에서 특히 민감한 문제로 다뤄진다.

이러한 쟁점들은 서로 분리된 문제가 아니라, 인공지능이 사회 속에서 작동하는 방식 전반과 연결되어 있다. 결국 AI 윤리는 다음 한 문장으로 수렴된다.

> **“이 기술이 누구를 위해, 어떤 기준으로 작동하는가?”**

---

### 6.3 인간 중심 AI(Human-centered AI)

AI 윤리가 사회적 논의에 머무르지 않고 실제로 작동하기 위해서는 **구체적인 기준과 절차**가 필요하다. 이러한 역할을 수행하는 것이 ‘**AI 윤리 가이드라인**’이다. 가이드라인은 기술 발전을 억제하기 위한 규제가 아니라, **인공지능이 사회적 신뢰 속에서 활용되기 위한 최소한의 합의**이다.

국제적으로 제시된 다양한 AI 윤리 가이드라인을 비교하면, 표현은 다르지만 공통된 방향성이 확인된다.

- 인공지능은 **인간의 존엄과 권리**를 침해해서는 안 된다.
- **인간이 최종적인 통제권**을 가져야 한다.
- 인공지능의 판단 과정과 결과에 대해 **책임의 주체**가 명확해야 한다.
- 가능한 범위 내에서 **설명**이 제공되어야 한다.

이러한 논의를 하나의 개념으로 정리한 것이 **인간 중심 AI**다. 인공지능의 효율이나 성능보다 **인간의 가치와 책임**을 우선에 두는 접근 방식으로, 인공지능은 인간의 결정을 대체하는 존재가 아니라 **인간의 판단을 보조하는 도구**로 위치 지워진다. 특히 법적·의료적·사회적 책임이 수반되는 영역에서는 **인간의 개입이 반드시 보장**되어야 한다.

인간 중심 AI는 선언적 가치에 그치지 않는다. **설계 단계 → 데이터 수집 → 알고리즘 구조 → 운영 방식 → 사후 평가**에 이르기까지 윤리적 고려가 포함되어야 하며, 시민과 사용자가 인공지능의 특성과 한계를 이해할 수 있도록 교육하는 것 역시 핵심 요소다.

> **인공지능의 방향을 결정하는 것은 기술 그 자체가 아니라, 그 기술을 어떻게 설계하고 사용할 것인가를 선택하는 인간의 판단이다.**

### 6.4 딥페이크: 진짜와 가짜의 경계가 무너질 때

**딥페이크(Deepfake)**는 AI 윤리 논의에서 가장 직관적이면서도 강력한 문제 사례로 자주 언급된다. 딥페이크란 인공지능, 특히 딥러닝 기반 생성 모델을 활용해 **실제 인물의 얼굴·음성·행동을 정교하게 합성한 가짜 콘텐츠**를 의미한다. 기술적으로 새로운 개념은 아니지만, 최근 몇 년 사이 급속도로 고도화되며 사회적 위험으로 인식되기 시작했다.

딥페이크가 문제가 되는 이유는 단순히 “가짜 영상이 만들어진다”는 사실 때문이 아니다. 핵심은 **신뢰의 붕괴**다. 현대 사회는 사진·영상·음성을 비교적 신뢰할 수 있는 증거로 활용해 왔다. 그러나 딥페이크 기술은 이러한 전제를 무너뜨린다. 이제 영상에 등장하는 인물이 실제로 그 말을 했는지, 그 행동을 했는지 확신하기 어려워졌다.

특히 **정치·범죄·성범죄** 영역에서 딥페이크의 위험성은 더욱 크다. 해외에서는 정치인의 발언을 조작한 영상이 유포되거나, 특정 인물을 대상으로 한 비동의 성적 합성물이 확산되며 심각한 피해를 초래한 사례들이 보고되었다. 이 경우 피해자는 자신의 얼굴과 목소리가 사용되었음에도 불구하고, **그것이 ‘가짜’라는 사실을 스스로 입증해야 하는 역설적인 상황**에 놓인다.

윤리적으로 딥페이크 문제는 세 가지 핵심 질문으로 정리된다.

1. 개인의 **초상권과 인격권**은 어디까지 보호되어야 하는가?
2. **기술을 만든 책임**과 **악용한 책임**은 어떻게 구분되는가?
3. 사회는 **가짜 콘텐츠를 어떻게 식별하고 대응**해야 하는가?

### 6.5 추천 알고리즘과 생성형 AI: 보이지 않는 영향력

#### 추천 알고리즘 — 선택을 돕는가, 조종하는가

추천 알고리즘은 딥페이크보다 훨씬 조용하게, 그러나 더 **넓은 범위**에서 인간의 삶에 영향을 미친다. 동영상 플랫폼·뉴스 서비스·쇼핑몰·음악 스트리밍에서 추천 알고리즘은 사용자가 무엇을 보고·읽고·구매할지를 결정한다.

표면적으로 추천의 목적은 ‘맞춤형 정보’ 제공이지만, 윤리적 문제는 여기서 발생한다. 추천 알고리즘은 중립적인 정보 전달자가 아니라, **특정 방향으로 사용자의 관심을 유도하는 구조**를 가진다. 자극적인 콘텐츠, 극단적인 의견, 감정을 자극하는 정보가 더 많이 노출되는 현상은 우연이 아니다. 이는 **체류 시간과 클릭 수를 극대화하도록 설계된 알고리즘의 결과**다.

이러한 구조는 사회적 분절과 정보 편향을 강화할 수 있다. 1장에서 다룬 **‘필터 버블’과 ‘에코 챔버’** 현상은 민주 사회에서 공론장의 건강성을 위협하는 요소로 지적된다. 추천 알고리즘의 윤리 문제는 “추천을 없앨 것인가”가 아니다. 핵심은 **어떤 기준으로 추천이 이루어지고 있는가**, 그리고 **사용자가 그 구조를 인식할 수 있는가**이다.

#### 생성형 AI — 창작의 주체는 누구인가

최근 생성형 인공지능은 글·이미지·음악·영상·코드까지 만들어 내며 창작 영역에 깊숙이 진입하고 있다. 이 기술은 생산성을 획기적으로 높일 수 있는 도구로 평가받는 동시에, **창작의 의미와 책임**에 대한 근본적인 질문을 던진다.

생성형 AI는 방대한 기존 콘텐츠를 학습해 새로운 결과물을 만들어 낸다. 이 과정에서 가장 큰 윤리적 쟁점은 **저작권과 창작 주체의 문제**다. AI가 만든 결과물은 누구의 것인가? 학습에 사용된 원작자의 권리는 어떻게 보호되어야 하는가? 또 다른 문제는 **정보의 신뢰성**이다. 생성형 AI는 그럴듯한 문장을 만들어 낼 수 있지만, **사실 여부를 스스로 검증하지 못한다**. 이로 인해 잘못된 정보나 허위 내용이 자연스럽게 생성·확산될 위험이 존재한다.

| 🧠 **토론 질문 — 생성형 AI** |
| :---- |
| · 생성형 AI가 만든 결과물은 ‘창작물’이라고 부를 수 있는가? 그 기준은 무엇인가? <br>· 인간이 AI의 결과물을 수정·편집했을 때, 창작의 주체는 누구라고 볼 수 있을까? <br>· 생성형 AI를 활용한 창작이 확산될수록, 인간의 창작 능력은 약해질까, 달라질까? |

| 🛠 **활동 6-2 — 생성형 AI 결과물 비판적 검토** |
| :---- |
| 생성형 AI를 활용해 글·이미지·요약 중 하나를 생성한다. 결과물에서 다음 항목을 점검한다. <br>① 사실 오류 가능성 / ② 출처 불명확성 / ③ 표현의 편향성 <br>“AI 결과물을 그대로 사용해도 되는가”에 대한 윤리 판단 중심의 보고서를 작성한다. (문제 제기 → 쟁점 분석 → 나의 판단 → 이유) |

### 6.6 트롤리 딜레마: 정답이 없는 선택

자율주행차가 사고를 피할 수 없는 상황에 놓였다고 가정해 보자. 직진하면 횡단보도의 보행자 5명이 다치고, 핸들을 꺾으면 인도의 보행자 1명이 다친다. **자동차는 어떤 판단을 해야 할까?** 그리고 그 ‘판단의 규칙’을 입력한 책임은 누구에게 있는가?

이것이 19세기 영국 철학자 **필리파 풋(Philippa Foot)**이 제시한 **트롤리 딜레마(Trolley Problem)**가 21세기 자율주행 시대에 다시 호출된 이유다. MIT 미디어랩이 운영한 실험 ⟪Moral Machine⟫은 전 세계 233개국 사용자에게 자율주행 시나리오 수십만 가지를 제시하며 데이터를 수집했다. 그 결과는 흥미로웠다.

- 서구권은 ‘젊은 사람’ 우선 경향이 높았다.
- 동아시아권은 ‘노인’ 우선 경향이 상대적으로 높았다.
- 라틴아메리카는 ‘여성/아이’ 우선 경향이 높았다.

> **문화에 따라 ‘무엇이 옳은가’의 답은 다르게 나타난다.**

이는 자율주행 윤리가 단순한 기술 문제가 아니라 **사회적 합의가 필요한 문제**임을 보여 준다. 어떤 답이 정답인지보다, **‘이 기준은 누가 정하는가, 어떻게 합의할 것인가’**가 더 본질적인 질문이다.

| 🧠 **토론 질문 — 트롤리 딜레마와 AI** |
| :---- |
| · 자율주행차가 사고 시 어떤 판단을 해야 하는지, 그 ‘판단 규칙’은 누가 정해야 하는가? <br>· 같은 상황에 대해 문화권마다 답이 다르다면, 글로벌 자동차는 어느 기준을 따라야 하는가? <br>· 인공지능에게 ‘선택의 책임’을 맡기는 것이 가능한가? 그 한계는 어디인가? |

---

이 장에서 살펴본 딥페이크, 추천 알고리즘, 생성형 AI, 자율주행 윤리는 서로 다른 기술처럼 보이지만, 공통된 윤리적 질문을 던진다.

> 이 기술들은 인간의 판단을 얼마나 대신하고 있는가?
> 우리는 그 작동 방식을 이해하고 있는가?
> 문제가 발생했을 때 책임은 누구에게 있는가?

**이 질문에 답하는 과정이 바로 인공지능 윤리다.**

### 7.1 산업별로 데이터는 어떻게 쓰이고 있는가

빅데이터는 산업마다 다른 얼굴로 쓰인다. 같은 ‘데이터 분석’이라는 이름을 달고 있어도, **목적과 활용 방식**이 다르다.

| 분야 | 활용 사례 | 사용되는 데이터 |
| :--- | :--- | :--- |
| **의료** | AI 진단 보조, 신약 개발, 개인 맞춤 치료 | 전자의무기록(EMR), CT/MRI 영상, 웨어러블 |
| **기상·재난** | 폭염·태풍 예측, 가뭄 경보, 미세먼지 알림 | 기온·강수·풍속 시계열, 위성 영상 |
| **교통** | 빠른 길 안내, 자율주행, 신호 최적화 | GPS 로그, 카메라·라이다, 교통량 센서 |
| **금융** | 사기 탐지, 신용 평가, 로보 어드바이저 | 거래 로그, 신용 이력, 시장 데이터 |
| **유통·쇼핑** | 추천 시스템, 수요 예측, 로켓 배송 | 클릭 스트림, 구매 이력, 재고 |
| **공공행정** | 인구 정책, 스마트 시티, 민원 분석 | 인구·세무·민원·교통 통계 |

이 책의 실습에서는 **누구나 무료로 받을 수 있는 공공데이터**를 사용한다.

### 8.1 Gemini 프롬프트 전략: ‘질문’이 분석의 절반이다

생성형 AI는 코드를 대신 작성해 주지만, **무엇을 물을지 정하는 것은 사람의 몫**이다. 분석용 프롬프트는 다음 6요소를 포함하는 것이 좋다.

| 요소 | 예시 |
| :--- | :--- |
| **역할** | “너는 파이썬 데이터 분석가야” |
| **목적** | “기온 데이터에서 장기 추세를 알고 싶어” |
| **데이터 정보** | “CSV, 컬럼은 date·avg_temp 두 개” |
| **요구 사항** | “1) 결측치 확인 2) 연도별 평균 그래프” |
| **제약 조건** | “외부 라이브러리는 pandas·matplotlib만” |
| **출력 형식** | “코드 → 실행 결과 → 한 줄 해석” |

#### 프롬프트 템플릿 (3단계)

```
[1단계] 너는 파이썬 데이터 분석가야. 다음 작업을 해줘.

[2단계] 데이터: {파일 경로 / 컬럼 / 행수}
요구: 1. 결측치 처리
      2. 평균 기온 시계열 그래프
      3. 분석 결과를 3줄로 요약

[3단계] 출력 형식:
- 코드는 ```python ... ``` 블록 안에
- 그래프 제목·축 라벨은 한국어로
- 마지막에 “이 데이터로 알 수 있는 것” 3줄 요약
```

| 📌 **읽을거리 — AI를 잘 쓰는 사람의 공통점** |
| :---- |
| AI가 만들어 준 코드를 그대로 돌리는 사람과, **결과를 검증하는 사람** 사이의 차이는 점점 커진다. AI는 그럴듯한 코드를 빠르게 만들지만, **데이터에 맞지 않는 컬럼명**을 그대로 쓰거나, **결측치를 무시**하거나, **잘못된 통계 해석**을 종종 한다. ‘AI가 짠 코드도 사람이 한 번 더 본다’는 원칙이 데이터 리터러시의 핵심이다. |

### 8.2 기온 데이터 시각화

#### 데이터 준비 (기상청 ASOS 일자료)

기상청 기상자료개방포털(`data.kma.go.kr`)에서 1904년부터의 일별 기온 데이터를 무료로 받을 수 있다. 우리는 ‘**서울**’ 관측소의 일평균 기온 시계열을 사용한다.

```python
import pandas as pd
import matplotlib.pyplot as plt

df = pd.read_csv('/content/drive/MyDrive/data/seoul_temp.csv',
                 encoding='euc-kr')
df.columns = ['date', 'avg_temp']          # 컬럼명 단순화
df['date'] = pd.to_datetime(df['date'])    # 날짜 타입 변환
df = df.dropna(subset=['avg_temp'])        # 결측치 제거
df.head()
```

#### ① 연도별 평균 기온 변화

```python
df['year'] = df['date'].dt.year
yearly = df.groupby('year')['avg_temp'].mean()

plt.figure(figsize=(12, 5))
yearly.plot(color='tomato')
plt.title('서울 연도별 평균 기온 (1907~)')
plt.xlabel('연도'); plt.ylabel('평균 기온(℃)')
plt.grid(alpha=0.3)
plt.show()
```

> **무엇이 보이나?** — 100년이 넘는 시계열에서 우상향(↑) 곡선이 뚜렷하다. **‘기온이 오르고 있다’**는 사실이 단순한 통계 표가 아닌, 한 장의 선그래프로 드러나는 순간이다.

#### ② 특정 날짜의 기온은 어떻게 변해 왔는가

```python
df['month'] = df['date'].dt.month
df['day']   = df['date'].dt.day

# 매년 8월 15일 기온
aug15 = df[(df['month'] == 8) & (df['day'] == 15)]
plt.scatter(aug15['year'], aug15['avg_temp'])
plt.title('매년 8월 15일 평균 기온 변화')
plt.show()
```

#### ③ 10년 뒤 기온 예측 (선형 회귀)

```python
from sklearn.linear_model import LinearRegression
import numpy as np

X = yearly.index.values.reshape(-1, 1)   # 연도
y = yearly.values                        # 평균 기온

model = LinearRegression().fit(X, y)

future = np.arange(yearly.index.max()+1, yearly.index.max()+11).reshape(-1,1)
pred = model.predict(future)
print(pd.DataFrame({'year': future.flatten(), 'pred_temp': pred.round(2)}))
```

> 📌 **주의** — 선형 회귀 한 줄로 미래를 예측하는 것은 **참고용**일 뿐이다. 실제 기후 모델은 수십 가지 변수와 비선형 관계를 함께 다룬다. ‘**모델은 답이 아니라 가설**’임을 잊지 말자.

### 8.3 영화 ⟪타이타닉⟫의 이야기는 사실과 같을까

> **“선원들이 ‘여자와 아이들 먼저!’를 외치며 구명보트에 태웠다.”** <br>
> **“1등석 승객은 여유롭게 보트에 올랐고, 3등석은 갑판으로 나가지 못했다.”**
>
> 영화 속 두 장면이 **실제 데이터에서도 같은 패턴**으로 나타날까?

이 절에서는 1,309명의 실제 탑승객 데이터를 분석하고, 머신러닝으로 잭(Jack)과 로즈(Rose)의 생존 여부를 직접 예측한다.

#### Step 5 — Feature Engineering: 이름에서 ‘호칭’ 뽑기

data['title'] = data['name'].map(
    lambda x: x.split(',')[1].split('.')[0].strip()
)

| 📌 **읽을거리 — 데이터 누수(Data Leakage)** |
| :---- |
| `boat` 열(구명보트 번호)은 **결과를 미리 알려 주는 정보**다. 이 열로 학습하면 모델 정확도가 98%로 치솟지만, 실제 ‘침몰 직전’ 시점에는 알 수 없는 정보다. **학습에서는 반드시 제외**해야 한다. 이런 함정을 ‘**데이터 누수(Data Leakage)**’라고 한다. |

#### Step 6 — 의사결정나무로 생존 예측

```python
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score

# 1) 전처리 — 성별 숫자화, 결측 행 제거
data['sex'] = data['sex'].map({'female':0, 'male':1})
data = data.dropna(subset=['age','fare','sibsp','parch','sex'])

features = ['pclass','sex','age','sibsp','parch','fare']
X = data[features]
y = data['survived']

# 2) 학습/평가 분할 (90/10)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.1, random_state=13)

# 3) 의사결정나무 (깊이 3)
tree = DecisionTreeClassifier(max_depth=3, random_state=13).fit(X_tr, y_tr)

# 4) 정확도
acc = accuracy_score(y_te, tree.predict(X_te))
print(f'Test Accuracy: {acc*100:.2f}%')   # 약 82%
```

#### Step 7 — 잭과 로즈의 운명

```python
# [pclass, sex, age, sibsp, parch, fare]
Jack = [3, 1, 19,  0, 0,   5.0]   # 3등실, 남성, 19세
Rose = [1, 0, 17,  1, 1, 100.0]   # 1등실, 여성, 17세

for name, p in [('Jack', Jack), ('Rose', Rose)]:
    prob = tree.predict_proba([p])[0]
    fate = 'Survived' if prob[1] > 0.5 else 'Dead'
    print(f'{name}: {fate} (확률 {max(prob)*100:.1f}%)')

# Jack: Dead     (약 86.5% 사망 예측)
# Rose: Survived (약 96.2% 생존 예측)
```

> **데이터는 거짓말을 하지 않는다.**
> 영화의 결말은 1912년 사회 구조와 일치한다. 3등실 남성 잭은 데이터상 매우 낮은 생존 확률을, 1등실 여성 로즈는 매우 높은 생존 확률을 갖는다.

## 제9장. 분석 결과의 공유 — 웹 시각화 (Folium)

> ### 핵심 질문
> **“카카오 ‘내 위치 보내기’와 분석가의 지도는, 같은 원리로 작동한다.”**

### 학습 목표

1. 위도(Latitude)·경도(Longitude) 좌표계의 기본 원리를 이해한다.
2. Folium으로 지도를 생성하고 마커·팝업·툴팁을 추가할 수 있다.
3. HTML 파일로 저장해 누구나 볼 수 있게 공유한다.
4. 공공데이터(보훈병원 CSV)를 지도에 시각화해 본다.

### 핵심 키워드

`위도/경도` · `Folium` · `Leaflet.js` · `Map / Marker / Popup` · `Icon color` · `tiles` · `CircleMarker` · `MarkerCluster` · `Choropleth` · `iterrows()`

### 9.1 위도와 경도: 지구 위 모든 점의 주소

#### 좌표계 한 장 정리

| 구분 | 기준 | 값의 범위 |
| :--- | :--- | :--- |
| **위도(Latitude)** | 적도(0°) 기준 남(S)/북(N) | −90° ~ +90° |
| **경도(Longitude)** | 본초자오선(그리니치) 기준 동(E)/서(W) | −180° ~ +180° |

> **위도 1° ≈ 약 111 km**

#### 한반도 좌표 범위

- 위도 **33°~43° N** (마라도 ~ 온성)
- 경도 **124°~132° E** (마안도 ~ 독도)
- 우리나라 표준시는 동경 **135°(GMT+9)** 기준

> 📌 **좌표 표기 순서 — `(위도, 경도)`**. Folium도 `(lat, lon)` 순서를 따른다.

| 📌 **읽을거리 — 카카오 ‘내 위치 보내기’의 원리** |
| :---- |
| 친구에게 카카오톡으로 ‘내 위치 보내기’를 누르면, 스마트폰의 GPS가 **위도·경도 두 숫자**를 읽어 서버에 전송한다. 받은 친구는 그 두 숫자를 지도(예: Daum/Naver Maps)의 좌표에 찍어서 마커로 보게 된다. **즉, 위치 공유 = 두 숫자의 전송 + 지도 위 점 찍기**다. Folium 실습은 정확히 이 흐름을 직접 만드는 것이다. |

### 9.2 Folium 라이브러리: 한 줄로 인터랙티브 지도

**Folium**은 파이썬 데이터를 받아 **JavaScript 기반 Leaflet.js 지도**로 변환해 주는 라이브러리다. 결과는 HTML 파일로 저장되어 어떤 브라우저에서든 열린다.

```python
!pip install folium
import folium
```

#### 실습 ① — 첫 지도 띄우기 (서울시청)

```python
m = folium.Map(
    location=[37.5665, 126.9780],  # 서울시청 좌표
    zoom_start=15
)
m   # Colab에서 셀에 그대로 입력하면 지도가 출력됨
```

| 옵션 | 의미 | 추천값 |
| :--- | :--- | :--- |
| `location` | 지도 중심 [위도, 경도] | 분석 대상의 평균 좌표 |
| `zoom_start` | 확대 정도 | 도시 단위 11~13, 동네 15~17 |
| `tiles` | 배경 지도 스타일 | `OpenStreetMap`(기본), `cartodb positron`(밝음), `cartodb dark_matter`(어두움) |

#### 실습 ② — 마커 + 팝업 + 툴팁

```python
loc = {'백석독수리': [36.838824, 127.182504]}

m = folium.Map(location=loc['백석독수리'], zoom_start=18)

folium.Marker(
    location = loc['백석독수리'],
    popup    = '내 위치',          # 클릭하면 보임
    tooltip  = '나여기있지롱',      # 마우스 올리면 보임
    icon     = folium.Icon(color='orange')
).add_to(m)

m
```

#### 실습 ③ — HTML 팝업 (이미지·링크 삽입)

```python
folium.Marker(
    location=loc['백석독수리'],
    popup=folium.Popup(
        '<a href="https://www.bs.ac.kr" target="_blank">백석대학교</a>'
        '<br><img src="logo.png" width="100">',
        max_width=300
    ),
    icon=folium.Icon(color='red')
).add_to(m)
```

#### 실습 ④ — HTML 파일로 저장 & 공유

```python
m.save('myLoca.html')
print('저장 완료! 브라우저에서 myLoca.html을 열어 보세요.')
```

저장된 HTML은 그 자체로 **완전한 인터랙티브 지도**다. 메일·블로그·카페에 첨부하면 누구나 클릭·확대해 볼 수 있다.

### 9.3 미션 — 나만의 여행 버킷리스트 지도

| 단계 | 할 일 |
| :--- | :--- |
| 1 | 가고 싶은 여행지 **3곳** 선정 |
| 2 | 구글맵에서 **위도·경도** 찾기 (장소 우클릭 → ‘이곳의 좌표는?’) |
| 3 | 딕셔너리에 저장 — `buckets = {'영국': [...], ...}` |
| 4 | 각 마커에 **다른 색상** 적용 (`red`/`blue`/`green`) |
| 5 | 툴팁에 사진(`<img>`) 삽입 |
| 6 | `tiles="cartodb positron"`로 깔끔한 배경 |
| 7 | `m.save("my_bucket_list.html")`로 저장 |

#### 참고 좌표

| 도시 | 좌표 (위도, 경도) |
| :--- | :--- |
| 영국 — 내셔널 갤러리 | (51.5089, −0.1283) |
| 뉴욕 — 브로드웨이 | (40.8124, −73.9627) |
| 로마 — 트레비 분수 | (41.9010, 12.4811) |
| 스위스 — 베른 | (46.9479, 7.4475) |
| 바르셀로나 — 사그라다 파밀리아 | (41.4036, 2.1744) |
| 몽골 — 고비사막 | (42.7952, 105.0324) |
| 평양 | (39.0293, 125.7428) |

#### 완성 코드 예시

```python
import folium

# 1. 데이터 준비
buckets = {
    '영국':  [51.5089,   -0.1283],
    '스위스': [46.9479,    7.4475],
    '몽골':  [42.7952,  105.0324],
}

# 2. 지도 생성 (스위스 중심, 밝은 배경)
m = folium.Map(
    location=buckets['스위스'],
    zoom_start=3,
    tiles='cartodb positron'
)

# 3. 마커 3개
folium.Marker(buckets['스위스'], popup='베른',     icon=folium.Icon(color='red')).add_to(m)
folium.Marker(buckets['영국'],   popup='런던',     icon=folium.Icon(color='blue')).add_to(m)
folium.Marker(buckets['몽골'],   popup='고비사막', icon=folium.Icon(color='green')).add_to(m)

# 4. HTML 저장
m.save('my_bucket_list.html')
```

### 9.4 실전 프로젝트 — 공공데이터로 그리는 ‘전국 보훈병원 지도’

이번 프로젝트의 목표는 **공공데이터 포털 → 데이터 정제 → Folium 시각화 → HTML 공유**까지 전 과정을 한 번에 경험하는 것이다.

| 항목 | 내용 |
| :--- | :--- |
| 데이터 출처 | **공공데이터 포털** (data.go.kr) |
| 파일명 | `국가보훈부_보훈의료 위탁병원 현황_20250101.csv` |
| 핵심 컬럼 | 위탁병원명 · 광역시도명 · 상세주소 · 전화번호 · 위도 · 경도 |
| 시각화 | 지역별 색상이 다른 `CircleMarker` |

#### Step 1 — 인코딩 감지 + CSV 로드

```python
import pandas as pd
import chardet

path = '/content/drive/MyDrive/data/보훈의료_위탁병원.csv'

# 한국어 CSV는 EUC-KR 인 경우가 많음
with open(path, 'rb') as f:
    enc = chardet.detect(f.read())['encoding']

df = pd.read_csv(path, encoding=enc)

cols = ['위탁병원명','광역시도명','상세주소','전화번호','위도','경도']
hos = df[cols].dropna()
hos.head()
```

#### Step 2 — 지도 중심 계산 + 지역별 색상 매핑

```python
import folium, seaborn as sns

# 1) 모든 병원의 평균 좌표 → 지도 중심
center = [hos['위도'].mean(), hos['경도'].mean()]
m = folium.Map(location=center, zoom_start=7)

# 2) 광역시도 개수만큼 색상 자동 생성
regions = hos['광역시도명'].unique()
palette = sns.color_palette('husl', len(regions))

region_colors = {
    r: '#%02x%02x%02x' % (int(c[0]*255), int(c[1]*255), int(c[2]*255))
    for r, c in zip(regions, palette)
}
```

#### Step 3 — CircleMarker 일괄 추가

```python
for _, row in hos.iterrows():
    color = region_colors.get(row['광역시도명'], '#808080')
    popup_html = (
        f"<div style='white-space:nowrap'>"
        f"{row['상세주소']}, {row['전화번호']}"
        f"</div>"
    )
    folium.CircleMarker(
        location  = [row['위도'], row['경도']],
        radius    = 5,
        color     = color, fill=True, fill_color=color,
        tooltip   = row['위탁병원명'],
        popup     = folium.Popup(popup_html, max_width=300)
    ).add_to(m)

m.save('보훈병원_전국_위탁현황.html')
```

#### 더 가 보기 (Folium 고급 기능)

| 기능 | 한 줄 설명 |
| :--- | :--- |
| `MarkerCluster` | 마커가 겹칠 때 자동 그룹핑 |
| `HeatMap` | 데이터 밀도를 색의 농도로 표현 |
| `Choropleth` | 행정구역(시·구·동)별로 색칠 — 인구·소득 등 |

| 🛠 **활동 9-1 — 우리 동네 지도 만들기** |
| :---- |
| 위 코드를 응용해 **우리 동네 카페 5곳**(또는 도서관·공원 등)의 인터랙티브 지도를 만든다. <br>① 좌표 직접 수집 → ② 색상 다르게 → ③ 사진·평점 정보 팝업 → ④ HTML 저장 후 친구에게 공유 |

| :---- |

## 마치며 — 데이터를 읽는 사람이 데이터에 끌려다니지 않는다

이 책은 작은 한 권의 입문서다. 그러나 우리는 이미 큰 길을 걸었다.

- 1부에서 **나의 일상이 곧 데이터**라는 사실을 만났고,
- 2부에서 **인류가 어떻게 기록과 시각화로 세상을 이해했는지** 살폈고,
- 3부에서 **인공지능이 어디에서 왔으며 어떤 윤리적 무게를 짊어졌는지**를 짚었으며,
- 4부에서 **직접 데이터를 손으로 만져 그래프와 지도를 만들었다**.

> **데이터 리터러시**란 결국, ‘**내가 보고 있는 숫자가 어떻게 만들어졌는지를 묻는 습관**’이다.

알고리즘이 점점 더 많은 결정을 대신하는 시대에, 그 질문을 던질 줄 아는 사람이 곧 미래를 설계하는 사람이다. 이 책의 마지막 페이지를 덮는 순간, 여러분의 데이터 여정은 비로소 시작된다.
